# 双滤波：串联是乘积，并联是加权和

## 是什么

P6.3b 给主滤波之后加了一个**可选的第二级**（`FILTER_ROUTING`，参数 id 146）：

| 接法 | 行为 |
| :--- | :--- |
| 0 `OFF`（默认） | 第二级**完全不进入**，走的是加这个功能之前那条代码路径 |
| 1 `SER` | 第二级吃第一级的输出，两级幅频**相乘**（dB 相加） |
| 2 `PAR` | 两级各自处理同一路输入，`out = (1 - blend) * A + blend * B` |

第二级是一份**独立的 12 dB SVF**（参数 `FILTER2_TYPE/CUTOFF/RES/DRIVE`，id 147–150），
每声部每侧一个实例。第一级是什么类型都不影响：阶梯低通、梳状、共振峰都各自只有一份状态，
不会被复制成两份——第二级永远是那个 SVF。UI 因此只提供 LP/HP/BP/NT/SEM 五种它真能渲染的类型；
补丁若把它设成 comb/formant，按低通渲染（`FilterType::second_stage_id()`，见下）。

## 实现里几个不能想当然的地方

1. **第二级不能在 `OFF` 时"顺手跑一下"。** 第一版把两级都渲染出来再按接法混合，默认关闭时
   也在混合里带进了第二级的输出（它的系数还没被设过），于是**所有旧音色**（sample 回放、sub、
   噪声、comb、共振峰、SEM）的音色都变了——9 条既有测试同时变红。现在的结构是：
   `OFF` 且已稳定 → 直接返回（第一级的输出就是 `voice_buf` 里的东西）；`OFF` 但正在从别的接法切回来 →
   只做一次交叉淡化到第一级；其余情况才跑第二级。
2. **`bridge_id()` 不能用在第二级上。** 它对 comb/formant 有 `debug_assert!(false)`（那是护栏：
   防止第一级的 comb/formant 静默变成低通）。第二级用单独的 `second_stage_id()`，把 comb/formant
   映射成低通（Rust 线格式里 `Sem` 是 6、C 里 `GS_FILTER_SEM` 是 4，这个坑 P6.3a 已经吃过一次）。
3. **并联需要"第一级看到的输入"。** 现有链路把滤波结果写回 `voice_buf`，所以并联时要在进入链路前
   把输入存一份（`filter2_in_buf`，按 makeup 前保存、使用时再乘回来）。串联直接用第一级的输出。
4. **不要再套一个 DC 阻断器。** 每个第一级分支本来就对自己的输出做了 DC 阻断；第二级（SVF）对残留
   直流是单位增益、不会放大它。多加一次会让"并联 blend 0"与"单级"差出 0.05 %，端点就不再逐位相同。
5. **测试装备的两个坑（都在 `src/dual_filter.rs` 的注释里）**：
   - 第一级的 `lp` 是**24 dB 阶梯 + tanh**，既不线性也不是 12 dB/oct；"两级响应相乘"和
     "两级各 12 dB/oct"这类断言必须用 `sem`（morph 0 的 SVF 低通，线性、12 dB/oct）；
   - 每次测量都带着音源电平，所以"乘积"要在**除以同一个宽开参考之后**再乘，否则会差出一个
     电平因子（第一版差了 26 dB）。

## 实测（真 wasm 门禁 `verify:audio`）

- **串联 = 两级响应之和（dB）**：600/1500/4000 Hz 三点最大偏差 **1.02 dB**；
- **两级 12 dB 低通同截止**：一个 −26.6 dB、两个 −53.8 dB（两个八度），斜率翻倍；
- **并联混合量单调**：1500 Hz 处 0.4 → −2.2 → −5.9 → −12.6 → −27.5 dB；
- **时域**：音符中途在串联/并联之间来回切、同时扫第二级截止与类型，峰值 0.172、
  最大相邻样本步进 **0.162**（阈值 0.5），不爆音。

Rust 侧另外用**逐位**断言钉住端点（并联 blend 0 = 单级、blend 1 = 第二级）、混合律的加权和、
串联乘积与逐带斜率（`src/dual_filter.rs`，13 条）。逐位比较是在同一个渲染链路里做的：
两个**独立**引擎实例之间的采样级比较不是可靠的装备（振荡器起始相位、平滑器残差都会进来），
门禁因此比的是**响应**。

## 兼容

`FILTER_ROUTING` 默认 0，旧补丁连第二级的分支都不进入；`test:dsp` 的 `rms 0.030806` 与
`verify:presets` 的 81 个预设指纹一字未动——这两条是每次改引擎都要先看的红线。
