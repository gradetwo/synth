# P6.5 过采样：抽取器选择、实测数字与两条教训

`OVERSAMPLE`（参数 id **166**，默认关）让**饱和的失真/滤波路径**在 2× 采样率下运算，再带限降回 1×。
关时逐位等于旧路径（`test:dsp` 的 `rms 0.030806` 与 `verify:presets` 的 `81 presets unchanged · ABI 8` 都没动）。

## 抽取器

`crates/synth-core/src/dsp/oversample.rs`：一份 **63 抽头 Kaiser 窗低通**（`fc = 0.21`、
`beta = 8`，对 2× 采样率归一化），**同一条系数表同时做插值与抽取**，因此整个 round trip 是纯延迟。
响应对 2× 采样率归一化、换算成 1× 频率后：

| 频率 | 19.2 k | 21.1 k | 23.0 k | 24.0 k | 24.2 k | 25.0 k | 26.9 k |
| :-- | --: | --: | --: | --: | --: | --: | --: |
| 衰减 | −2 dB | −12 dB | −37 dB | −71 dB | −97 dB | −85 dB | −107 dB |

半带没有保护带，「刚好在 Nyquist 下面那个八度会折到自己身上」——和硬同步抽取器注释里记的是同一个坑，
所以这里把截止压低、留出保护带。之所以是 63 而不是硬同步的 95：这条路径每个声部都要跑，
63 抽头已经足够（24.2 kHz 处 −97 dB），而成本只有一半。

应用位置：

- **每声部滤波路径**（`Engine::render_voice`）：up → 整个滤波链在 2× 下跑 → down。包含 ladder（`lp`）
  与 C 桥的 SVF 家族（`hp/bp/nt/sem`）以及第二级（P6.3b），C 桥的截止频率按 2 倍传进去。
  `comb` / `formant` 是线性滤波器（没有饱和器），过采样只有成本没有收益，直接跳过（延迟也因此为 0）。
- **FX 链里的 DRIVE 插入**（`Engine::drive_oversampled`）：up → 厂商 Overdrive 在 2× 下跑 → down。
  Overdrive 是逐样本的无记忆波形整形，可以原地跑。

共享调制的自由图（`FX_GRAPH`）暂不参与：它没有逐节点延迟补偿，硬开会让 drive 节点与干路错 31 个样本。
图模式因此保持 1× 的 drive（见 `Engine::oversampling` 的注释）。

## 频域实测：26.1 dB

场景：OSC1 正弦、note 45（110 Hz）、满量程 FX DRIVE（amt/mix = 1）、滤波全开、
**先清调制矩阵**（`gs_set_mod_route(i, 0, 0, 0, 0)`）、主音量 0.1 让主限幅器留在线性区。
1 整秒、矩形窗、精确 bin（门禁 `verify-audio.mjs` 与 Rust 单测同一套）：

| 模式 | 非谐波能量（相对信号 RMS） |
| :-- | --: |
| 1× | **−33.4 dB** |
| 2× | **−59.5 dB** |

**下降 26.1 dB**（门禁要求 ≥12 dB）。基频只动 −0.00 dB，说明是混叠被拿走，不是电平变了。

### 教训一：不能用「半格 bin」量混叠

最初按硬同步笔记的启发，在 `f0·(k+0.5)` 这些「谐波中间」的 bin 上取样。对 110 Hz 的方波，
折回落在 `n·fs − k·f0`，它**不是**栅格的固定比例（`fs/f0 = 436.36`），半格 bin 全部落空，
量到的是噪声底。正确做法是 **Parseval**：把全部谐波 bin 的能量（幅度读数是 A/2，功率 `2m²`）求和，
从总能量里减掉，剩下的就是「不在谐波上」的能量，落在哪里都能收到。

### 教训二：单测的 host 构建与 wasm 门禁不是同一个数

同一场景、同一份 wasm 源码：

| 构建 | 1× | 2× |
| :-- | --: | --: |
| wasm 门禁 | −33.4 dB | −59.5 dB（26.1 dB） |
| host `cargo test` | −33.0 dB | −43.6 dB（10.6 dB） |

1× 对得上，2× 差 16 dB，指向 host 与 wasm 在硬削波路径上的 codegen / `f32::exp2` 末位差异。
因此 **12 dB 的硬线由 wasm 门禁持有**，Rust 单测只钉方向（≥8 dB）与抽取器的带宽（模块里另有精确的
阻带单测：2× 域 30 kHz 的音不能变成 18 kHz 的镜像）。相位扫描（advance=0…11）显示 host 的数是稳定的，
不是随机抖动。

## 延迟与补偿

round trip 是线性相位，代价是固定 **31 个 1× 样本**（约 0.65 ms @48 kHz）。

- 整个声部的滤波路径都被同一对 FIR 延迟，路径之间不会梳状抵消；图模式不参与，也就没有未补偿的并联支路。
- DRIVE 插入的 **干路被延迟同样多**（`delay_samples`），所以它自己的 dry/wet 交叉淡化仍对齐——
  否则 1× 的干声会和 2× 的湿声错开 31 个样本而梳状染色。
- `Engine::oversample_latency()` 把该值报出来（开 31 / 关 0），宿主若要和 1× 逐样本对齐，
  补偿这个数即可。Rust 单测断言该值与 `OS_LATENCY` 一致。

开关急变（以及驱动量急变）的时域断言：全程有限、≤1.0、`nan_events == 0`、最大相邻样本跳变 < 0.25。

## 成本（`scripts/bench.mjs --oversampled`）

同一台机器、同一时刻连续跑两次（host load 6.5/8，计时判定被 bench 自己标为不可信，看原始均值）：

| 场景 | 1× mean | 2× mean | 预算占用 |
| :-- | --: | --: | --: |
| 16 音密集 patch | 442 µs | 829 µs | 16.6% → **31.1%** |
| 同一 patch + 2 s IR 混响 | 653 µs | 842 µs | 24.5% → 31.6% |

约 **1.9×** 的 CPU，仍在 60% 预算内（`overBudget`、`gs_alloc_violations() == 0` 不受影响）。

## DSP 指纹

两种模式各一份基线，都进门禁：

- 关（默认）：`tests/dsp-baseline.json`，`rms 0.030806`，`npm run test:dsp`；
- 开：`tests/dsp-baseline-2x.json`，`rms 0.030946`，`npm run verify:dsp:2x`（`--oversampled`）。
