# P6.5 过采样：抽取器选择、实测数字与两条教训

`OVERSAMPLE`（参数 id **166**，默认关）让**饱和的失真/滤波路径**在 2× 采样率下运算，再带限降回 1×。
关时逐位等于旧路径（`test:dsp` 的 `rms 0.030806` 与 `verify:presets` 的 `81 presets unchanged · ABI 8` 都没动）。

## 抽取器

`crates/synth-core/src/dsp/oversample.rs`：一份 **63 抽头 Kaiser 窗低通**（`fc = 0.21`、
`beta = 8`，对 2× 采样率归一化），**同一条系数表同时做插值与抽取**，因此整个 round trip 是纯延迟。
响应对 2× 采样率归一化、换算成 1× 频率后：

| 频率 | 19.2 k | 21.1 k | 23.0 k | 24.0 k | 24.2 k | 25.0 k | 26.9 k |
| :-- | --: | --: | --: | --: | --: | --: | --: |
| 衰减 | −2 dB | −12 dB | −37 dB | −71 dB | −97 dB | −85 dB | −107 dB |

半带没有保护带，「刚好在 Nyquist 下面那个八度会折到自己身上」——和硬同步抽取器注释里记的是同一个坑，
所以这里把截止压低、留出保护带。之所以是 63 而不是硬同步的 95：这条路径每个声部都要跑，
63 抽头已经足够（24.2 kHz 处 −97 dB），而成本只有一半。

应用位置：

- **每声部滤波路径**（`Engine::render_voice`）：up → 整个滤波链在 2× 下跑 → down。包含 ladder（`lp`）
  与 C 桥的 SVF 家族（`hp/bp/nt/sem`）以及第二级（P6.3b），C 桥的截止频率按 2 倍传进去。
  `comb` / `formant` 是线性滤波器（没有饱和器），过采样只有成本没有收益，直接跳过（延迟也因此为 0）。
- **FX 链里的 DRIVE 插入**（`Engine::drive_oversampled`）：up → 厂商 Overdrive 在 2× 下跑 → down。
  Overdrive 是逐样本的无记忆波形整形，可以原地跑。

共享调制的自由图（`FX_GRAPH`）**从 P9.4（v1.106.0）起也参与**：DRIVE 节点在 2× 下跑，并由逐节点
PDC 把并联支路与干路重新对齐（见文末「P9.4：自由图的逐节点 PDC」）。在此之前它刻意不参与，因为
没有逐节点延迟补偿，硬开会让 drive 节点与干路错 31 个样本。

## 频域实测：26.1 dB

场景：OSC1 正弦、note 45（110 Hz）、满量程 FX DRIVE（amt/mix = 1）、滤波全开、
**先清调制矩阵**（`gs_set_mod_route(i, 0, 0, 0, 0)`）、主音量 0.1 让主限幅器留在线性区。
1 整秒、矩形窗、精确 bin（门禁 `verify-audio.mjs` 与 Rust 单测同一套）：

| 模式 | 非谐波能量（相对信号 RMS） |
| :-- | --: |
| 1× | **−33.4 dB** |
| 2× | **−59.5 dB** |

**下降 26.1 dB**（门禁要求 ≥12 dB）。基频只动 −0.00 dB，说明是混叠被拿走，不是电平变了。

### 教训一：不能用「半格 bin」量混叠

最初按硬同步笔记的启发，在 `f0·(k+0.5)` 这些「谐波中间」的 bin 上取样。对 110 Hz 的方波，
折回落在 `n·fs − k·f0`，它**不是**栅格的固定比例（`fs/f0 = 436.36`），半格 bin 全部落空，
量到的是噪声底。正确做法是 **Parseval**：把全部谐波 bin 的能量（幅度读数是 A/2，功率 `2m²`）求和，
从总能量里减掉，剩下的就是「不在谐波上」的能量，落在哪里都能收到。

### 教训二：单测的 host 构建与 wasm 门禁不是同一个数

同一场景、同一份 wasm 源码：

| 构建 | 1× | 2× |
| :-- | --: | --: |
| wasm 门禁 | −33.4 dB | −59.5 dB（26.1 dB） |
| host `cargo test` | −33.0 dB | −43.6 dB（10.6 dB） |

1× 对得上，2× 差 16 dB，指向 host 与 wasm 在硬削波路径上的 codegen / `f32::exp2` 末位差异。
因此 **12 dB 的硬线由 wasm 门禁持有**，Rust 单测只钉方向（≥8 dB）与抽取器的带宽（模块里另有精确的
阻带单测：2× 域 30 kHz 的音不能变成 18 kHz 的镜像）。相位扫描（advance=0…11）显示 host 的数是稳定的，
不是随机抖动。

## 延迟与补偿

round trip 是线性相位，代价是固定 **31 个 1× 样本**（约 0.65 ms @48 kHz）。

- 整个声部的滤波路径都被同一对 FIR 延迟，路径之间不会梳状抵消；图模式不参与，也就没有未补偿的并联支路。
- DRIVE 插入的 **干路被延迟同样多**（`delay_samples`），所以它自己的 dry/wet 交叉淡化仍对齐——
  否则 1× 的干声会和 2× 的湿声错开 31 个样本而梳状染色。
- `Engine::oversample_latency()` 把该值报出来（开 31 / 关 0），宿主若要和 1× 逐样本对齐，
  补偿这个数即可。Rust 单测断言该值与 `OS_LATENCY` 一致。

开关急变（以及驱动量急变）的时域断言：全程有限、≤1.0、`nan_events == 0`、最大相邻样本跳变 < 0.25。

## 成本（`scripts/bench.mjs --oversampled`）

同一台机器、同一时刻连续跑两次（host load 6.5/8，计时判定被 bench 自己标为不可信，看原始均值）：

| 场景 | 1× mean | 2× mean | 预算占用 |
| :-- | --: | --: | --: |
| 16 音密集 patch | 442 µs | 829 µs | 16.6% → **31.1%** |
| 同一 patch + 2 s IR 混响 | 653 µs | 842 µs | 24.5% → 31.6% |

约 **1.9×** 的 CPU，仍在 60% 预算内（`overBudget`、`gs_alloc_violations() == 0` 不受影响）。

## P9.4：自由图的逐节点 PDC（v1.106.0）

**参与节点**：`Engine::node_oversampled(kind) = Drive`（DRIVE 是无记忆波形整形、本质折叠频率；
CRUSH 同类，本批未开；EQ/延迟/混响/合唱/镶边/移相/瞬态整形是线性或纯增益律，**只补偿不上采样**）。

**PDC 公式**（节点索引即拓扑序，单次前向解）：

```
own(v)     = 31 if (v 是 2× 节点且本块运行) else 0
lat(v)     = max( max_{输入边}(lat(src)), own(v) )        // 干声源 lat = 0
M          = max_v lat(v)
w(v,edge)  = M − lat(src)                                  // 干声源→输出汇走 lat=0，故整段 M
总延迟      = OS_LATENCY + M
```

两条容易搞错的不变量（第一条正是本批踩的坑）：

1. **一个 2× 节点的 up/down 往返是它自己的*输出*延迟，只能算一次**。节点干/湿交叉淡化的对齐由
   **节点内部**负责（`drive_oversampled_node` 把干声也 `delay_by(…, OS_LATENCY)`，与链模式
   `drive_oversampled_amt` 同源）。**若 PDC 再把往返加到节点*输入*上，就会补两遍**：干腿 +62、
   湿腿 +31 ⇒ `blend_node` 做 31 样本错位的交叉淡化 ⇒ 图输出被梳状染色。
2. **每条输入边要独占一条历史**（不能原地延迟节点缓冲：同一节点被两个读者以不同权重读取时会被
   叠加）。干声总线是共享缓冲，每块只按「本节点请求的最大干声权重」延迟一次，节点边只补差值。

**踩坑记录（值得记住的形状）**：第一版把往返算了两遍，症状是**图模式 2× 的混叠比 1× 还差 25 dB**
（−33.0 → −7.1 dB），而**链模式同代码是下降 26 dB**；把真机的节点输入喂回两条路径，两者**逐位相同**，
所以「节点之后」被误当成嫌疑区。真正的诊断线索是**节点混合后的输出**，而不是往返输出：往返正确、
混合错误 ⇒ 一定在「节点内部的对齐」或「输入的额外延迟」上，二者只能有一个算往返。

**实测（真 wasm，note 45、1 s、精确 bin / BH-7）**：

| 场景 | 1× | 2× | 变化 |
| :--- | ---: | ---: | ---: |
| 链 DRIVE | −33.43 | −59.55 | **−26.12 dB** |
| 图 DRIVE（修前） | −33.43 | −33.43 | 0.00 dB（wasm 门禁读 −7.1） |
| 图 DRIVE（修后） | −33.43 | **−59.54** | **−26.11 dB** |
| 图 + 并联 EQ 支路 | −33.52 | −58.94 | −25.42 dB |

**时域**：图 2× vs 链 2× 互相关 **1.000000 / 0.999983 at lag 0**（最强证据：节点混合输出与链 insert
等价）；图 2× vs 图 1× 为 0.998292，**最佳 lag = 62 = `gs_oversample_latency()`**（61→0.997682、
63→0.989140，峰正好在 62）——链的同一比较也是 0.998292，所以 0.998 是「1× 硬驱方波 vs 2× 带限方波」
的物理上限，不是对齐误差。**延迟上报**：开关开且图 2× 活跃时 **62 样本 / 1.29 ms @48 kHz**
（`OS_LATENCY + M`，M=31）；`graph_latency()` 报图自身份额。

**成本**：整链 16 声部 p50 **1099 → 1325 µs（1.21×）**，因为只有 DRIVE 节点跑 2×（链模式的 DRIVE
本来就是 2×，图模式现在同名同价）。体积 dist +5.0 KB、最大 wasm gzip +0.6 KB。

**既存边界（不是本批引入）**：图 patch 上 switch/驱动量急变的最大相邻跳变 **1.8088827（v1.105.0，
无 P9.4 代码）** vs 1.795138（含 P9.4）——那是**声部滤波路径自己的 31 样本往返**在硬驱方波上换挡，
用 A/B 对照确认过；P6.5 场景（无并联支路、非满驱）仍 < 0.25。

**「编号重叠」不成立（2026-09-15 复核并更正）**：这里原来写着 `graph_param_field` 的
`base <= id < base + FX_SLOTS` 让节点区与其它参数撞号，并给了三个算式。**那三个算式全是错的**
（`FX_NODE_OUT_GAIN + 1 = 132 ≠ FX_DELAY_MIX = 35`、`FX_NODE_TO_OUT + 5 = 130 ≠ FX_PARALLEL3 = 90`、
`FX_NODE_IN1 + 5 = 106 ≠ FX_EQ_ON = 157`），真算式是 `FX_NODE_OUT_GAIN + 6 == OSC_FM`（131+6=137）。
节点块是**干净连续的 36 个 id**：六个字段的 base 恰好相距 `FX_SLOTS = 6`，半开区间
`[101,107) [107,113) [113,119) [119,125) [125,131) [131,137)` **两两不相交且铺满 `[101,137)`**，
每个 id 都解码到自己那格，`132..136` 是**空缺号**、没有任何普通参数落在块内。所以
「宿主无法把 6 个节点清干净」不成立，`Params::set` 的 `slot < FX_SLOTS` 守卫是**防御性**的
（没有真实 id 会走到它）。**本文件上面那条「过采样往返补偿被算了两遍」才是 P9.4 那次 2× rms
的真因**，两件事原被并成了一句话。逐 id 影响面与「为什么不重排编号」见
`docs/notes/node-param-ids.md`（轨道 `pid`，2026-09-15），并由 Rust
`node_block_does_not_shadow_any_ordinary_parameter` 等 4 条与 `src/audio/node-ids.test.ts` 5 条钉住。
