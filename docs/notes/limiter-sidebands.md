# §一.44 推入限幅器时的 `k·f0 ± 40 Hz` 侧带：机制、修法与实测

上游现场在 `.tmp/pnoise-report.md` §3b：用 `PATCH_GAIN`（id 78）把单声部推过主限幅器
（`PATCH_GAIN ≈ 6 / 8`）后，BH-7 尺子读 **−35.2 / −35.1 dB**，增益轨迹有 **1.1 dB** 的峰-峰纹波，
其频谱主峰在 **f0 与 40 Hz**，音频里最强的离格分量在 **k·f0 ± 40 Hz**；报告据此写「偏移与 f0 无关
（55/110/220/440 Hz 全是 ±40 Hz）」。

本批的结论有三条：**（1）40 Hz 不是固定调制频率**，那是只测 A 音造成的巧合；真正决定它的是
「采样相位图案」的重复率。**（2）机制是限幅器的峰值检波器被波形的边沿采样高度调制**，
但真正把它送进增益的是「两个波峰之间也在释放」这一步。**（3）修法不需要新参数、不需要新状态**：
峰值仍高于 ceiling 时不释放。修后同一现场 **−58.3 dB**、纹波 **0.000 dB**，
`test:dsp` / `verify:dsp:2x` / 91 条指纹**逐位不变**。

## 1. 机制

### 1.1 检波器是**逐采样**的，而且每个波形周期重置一次

`engine.rs` 的限幅段：

```rust
let decay = (-1.0 / (LIMIT_PEAK_HOLD_S * sr)).exp();
...
let abs = in_l.abs().max(in_r.abs());
self.limit_peak = if abs > self.limit_peak { abs } else { self.limit_peak * decay };
let need = if self.limit_peak > LIMIT_CEILING { LIMIT_CEILING / self.limit_peak } else { 1.0 };
```

对 110 Hz 锯齿，`|x|` 的爬升速率（`2·A·f0 ≈ 350 /s`）远大于衰减速率（`1/τ = 20 /s`），
所以爬升段 `limit_peak ≈ |x|`；每到一个波形边沿（幅值尖峰）检波器就被重置，然后在周期余下部分
按 50 ms 指数衰减。于是 `need`（以及 `limit_target`、`limit_gain`）每个周期出现一次「谷」。

### 1.2 谷的深度由**边沿的采样高度**决定，而那是会抖的

真实信号的边沿只有 ~3 个采样宽（实测 2 s 内最大单步 −0.24、|step|>0.9 的跳变 380 个，
其余 99.7% 的采样 |step| < 0.1）。边沿落在两个采样点之间的哪个小数相位，决定「最近的采样」
有多高：**每周期采样峰值抖动 sd/mean = 4.4%**（110 Hz 锯齿，实测），
它与每周期的增益谷深**相关系数 −0.908**（谷越深 ↔ 采样峰越高）。

4.4% 的增益调幅，边带就在 `20·log10(0.044/2) ≈ −33 dBc` 量级——正是观测到的 −35 dB 地板。

### 1.3 「40 Hz」= 采样相位图案的重复率，不是绝对频率

采样相位每周期前进 `frac(fs/f0)`：110 Hz 每周 436.3636 个采样，相位图案要 11 个周期
（= 4800 采样 = 0.1 s）才回到原处。于是抖动图案是周期 11 周期的准周期信号，它的离散谱落在
`f0/11 = 10 Hz` 的整数倍上；四个 A 音（55/110/220/440 Hz）**恰好都整除 11 周期**，
`40 Hz` 在四条谱里都是这条网格上的强线（110 Hz 是 4 次谐波、220 是 2 次、440 是基频、55 是 8 次），
所以上游只测 A 音时看到「全是 40 Hz」。**换成非 A 音就不是 40 Hz**（同一现场、真 wasm、4 s：

| 音 | f0 | 最强离格线（相对最强线 dB） | 与最近谐波的偏移 |

### 1.4 直接证据：把「边沿」拿掉，调制就没了

真 wasm、note 45、`PATCH_GAIN 6`、4 s（BH-7 离格地板，越低越好）：

| 波形 | 修前地板 | 修后地板 | 单步 |
| :-- | --: | --: | --: |
| sine（无沿） | −92.1 dB | −123.1 dB | 0.014 |
| triangle（角点，无跳变） | −70.6 dB | −117.1 dB | 0.009 |
| **saw** | **−34.8 dB** | **−58.3 dB** | 0.815 |
| **square** | **−36.7 dB** | **−60.2 dB** | 0.808 |

在已验证的 JS 复刻里把真实输入信号做低通消融（同一循环、同一波形）：
3 kHz 低通把 40 Hz 调制从 −2.8 dB 压到 −28.4 dB，1 kHz 压到 −44.7 dB；
而**理想单采样跳变**的合成锯齿在 110 Hz 只有 −32 dB（真实信号 −2.8 dB）——
差别就在 BLEP/滤波那条 3 采样宽的边沿。

### 1.5 三个常数的因果实验（JS 复刻，先对过账）

复刻（`simLoop`，与引擎逐项对照过：稳态增益 0.6011..0.6812 vs 引擎 0.601..0.682，
纹波 1.09 vs 1.00 dB，重建音频地板 −34.0 vs 引擎 −35.3 dB）上的扫描，
每个格子是「地板 dB / 增益峰-峰纹波 dB」，真信号 note 45：

| 只改一个常数 | f0=110 | f0=220 | f0=440 | 结论 |
| :-- | :-- | :-- | :-- | :--- |
| 基线（hold .05 / release .15 / ceiling .95） | −35.0 / 1.14 | −34.2 / 0.77 | −34.0 / 0.62 | — |
| `LIMIT_RELEASE_S` .15 → 1.5 | −43.6 / 0.26 | −44.3 / 0.19 | −44.0 / 0.16 | 释放变慢只**线性地**减小纹波，压不下去（谷的抖动还在） |
| `LIMIT_RELEASE_S` .15 → 2.5 | −46.7 / 0.18 | −47.4 / 0.12 | −46.7 / 0.11 | 同上，回到 f0 网格上的下坡棘轮 |
| `LIMIT_PEAK_HOLD_S` .05 → .2（检波器保持） | −43.2 / 0.39 | −47.8 / 0.20 | −50.5 / 0.10 | 有效，但**保持长度**要长到覆盖图案周期才稳 |
| `LIMIT_CEILING` .95 → .5 | 1.09 纹波 | 0.24 | 0.24 | 只改工作点（推过 ceiling 的深度），**不改调制频率** |
| `LIMIT_CEILING` .95 → .99 | 0.61 纹波 | 0.16 | 0.16 | 同上 |
| 合成理想锯齿 f0=110/220 | 40 Hz 调制 **−32 / −17 dB** | | | 没有边沿细节就没有调制 |

⇒ **没有任何单个常数能把 40 Hz 侧带压到地板**：`LIMIT_CEILING` 只改深度；
`LIMIT_RELEASE_S` 改斜率但抖动仍进增益；`LIMIT_PEAK_HOLD_S` 要长到覆盖相位图案周期才见效，
而那等于把释放推迟几百毫秒。真正要做的是**别让抖动进增益**。

## 2. 修法：峰值仍在 ceiling 之上时不释放

```rust
if need < self.limit_target {
    self.limit_target = need;
    self.limit_slope = (self.limit_gain - need) / LOOKAHEAD as f32;
} else {
    // 原来无条件按 release_step 恢复；现在只有回到 ceiling 以下才恢复
    let step = release_step * f32::from(u8::from(need >= 1.0));
    self.limit_target = (self.limit_target + step).min(need);
}
```

- `need == 1.0` ⟺ `limit_peak <= LIMIT_CEILING`，所以「回到 ceiling 以下」不需要新状态。
- 没有新参数 id、没有动 `PARAM_COUNT`/ABI、没有新字段。
- 不动作时（`need` 恒为 1.0）路径**逐位不变**：`limit_gain` 恒为 `1.0f32`，乘法恒等。
- 写成了**无分支**形式（`f32::from(u8::from(need >= 1.0))`）：先写成 `else if need >= 1.0`
  的写法会破坏 LLVM 原来的 branchless 目标更新，wasm gzip 从 74.91 → **75.19 KiB（超 75.0 线）**；
  无分支写法只 +13 B（74.9121 → **74.9248 KiB**），门禁 `verify:budget` 通过。

副作用是好的：增益在持续音上变成**分段常数**（取过去一段的所需增益最小值），
不再每周期锯齿 → 泵动与侧带一起消失；瞬态仍然立刻下压（`need < limit_target` 分支没动），
释放从「信号真正回落到 ceiling 以下」开始。

## 4. 门禁与自证

**两条门禁都跑一组音高，不是单音**：note 45 (110 Hz)、57 (220 Hz)、**69 (440 Hz，实测最差)**。
理由：修后的残差是软削波器自己的地板，而它**在高音最差**（−58.3 / −55.2 / −51.9 dB），
只钉 110 Hz 会让「只影响高音的回归」从两条门禁中间溜过去。

- Rust：`crates/synth-core/src/engine.rs` 的
  `the_limiter_does_not_modulate_the_bus_at_the_phase_rate`——每个音 1 s 渲染 + BH-7 离格地板 < −50 dB，
  同时断言峰值 ≤ 1.0、无 NaN、单步 < 1.2×峰值、增益峰-峰 < 0.5 dB；外加 sine 控制 < −100 dB。
- 真 wasm：`scripts/verify-audio.mjs` 的「§一.44」段——note 45 用 4 s（承载侧带细节），
  57/69 用 1 s；每条都断言离格地板 < −50 dB、增益峰-峰 < 0.5 dB、峰值 ≤ ceiling、全采样有限；
  控制项 sine (< −100 dB) 与 triangle (< −95 dB) 证明尺子读的不是自己。
- **为什么允许 1 s**：读数由「采样相位图案」决定，而图案对固定音高是稳定的——
  连续 8 次 note-on（会依次走 `phase_seed`）在 1 s 与 4 s 上读出的三个地板一致到 0.1 dB
  （−58.3 / −55.2 / −51.9）。1 s 让这一段只多花不到一秒的 CPU。
- **−50 dB 这条线的来源**：不是任务书里的示例值，而是**软削波器的地板**——
  固定增益把峰值推过膝 0.82（不动作限幅器）实测 −55…−57 dB，所以限幅器自己的贡献已经低于它；
  线取 −50 意味着修后最差音（440 Hz，−51.9）留 1.9 dB 余量，而修前三个音是 −35.2/−34.1/−33.9，
  牙齿 15 dB 以上。**以后若有人动 `soft_limit` 的膝或 ceiling，这条线的口径要重看。**
- 自证（临时把 `else` 里那一行还原成无条件 `release_step`、重建 wasm 再跑同一条门禁）：
  **包含 440 Hz 的那条**、泵动那条、以及两条控制都红，修法版全绿；原文见交付报告。

## 5. 留下的问题

1. 修后的地板是**软削波器的地板**（−55…−60 dB @ 输出峰值 ~0.91）。要再低只能动
   `soft_limit` 的膝/ceiling 组合，那是响亮度的取舍，本批不碰。
2. 相位图案长度 `m`（`48000/f0 = P/Q` 的最简分数分母）可以很大（116.5 Hz 是 47 周期 = 0.4 s），
   所以「取样保持窗口」类的修法（本批试过：增益保持、检波器保持）都不稳；
   本批采用的「不释放」修法与图案无关，这才解释了它为什么在所有音高上一致。
3. `true_peak` 表头那条 `((in_l + out_l) * 0.5)` 是输入与**128 采样前的输出**取平均，
   不是真正的 inter-sample 估计；本批没动它（它只喂表头）。
