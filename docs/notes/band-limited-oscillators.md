# 普通振荡器的带限（P9.1b）：把硬同步那套搬到锯齿/方波/三角

P9.1a 的调查结论是：纯正弦的「−84…−102 dB 底噪」是测量伪影，而**锯齿/方波/三角的
−37…−49 dB 是真实底噪**，来源是 DaisySP 的两点 polyBLEP 混叠（离线模型与引擎差 ≤0.3 dB）。
P9.1b 就是按那份报告的「方案 B」动手：把 P6.2b 为硬同步写的**专用带限振荡器**复用到普通
振荡器上。这是本计划里少数的**有意音色改变**批次，所以基线是显式重录的，不是悄悄变的。

## 做了什么

- `crates/synth-core/c_bridge/gs_daisy.cpp` 新增 `gs_voice_osc_bandlimit_block()`：普通锯齿 /
  方波 / 脉冲 / 三角走这条路。它复用硬同步那一整套已经验证过的零件 —— 同一张 `g_blep` /
  `g_blamp` 表（启动时在 BSS 里算，不是动态全局构造）、同一个 `sync_kernel`（含 P9.1c 修好的
  跨跳变格）、同一个 `sync_emit` 环形累加器、同一个 95 抽头 Kaiser 抽取器、同一个 2× 域。
  每个采样在 2× 域里发**朴素波形**，再在同一个判据上补：周期回绕 BLEP（锯齿/方波/脉冲）、
  方波的 pw 边沿 BLEP、三角的两个斜率折点 BLAMP（`p=0` 与 `p=0.5`，幅度 ∓8·inc）。
- **正弦、波表、采样、噪声保持原路径**（正弦本来就 ≤ −119 dB）。
- **延迟补偿**：新路径的固定延迟 = 抽取 FIR 群延迟 `(95−1)/2 / 2 = 23.5` 个基率样本。旧路径
  补一次 `gs_voice_osc_delay_block()`（23 整数样本 + 4 点 Lagrange 半样本插值），使两者同相；
  unison 在求和后补一次（和是线性的）。延迟值由 `gs_osc_bandlimit_latency()` 导出，Rust 侧不
  重复定义。
- 顺手把 `sync_emit` 的热循环从「每抽头一次浮点乘 + 两次范围判断」改成「浮动计数器 += R」，
  环缓冲 68 → 128（2 的幂）用掩码回绕。

- **延迟**：单声部 **23.5 样本**（两个振荡器与旧路径正弦之间的相位已补偿）。
- **体积**：dist **1677.6 → 1683.0 KB**（阈值 1678 → **1684**）；最大 wasm gzip

- **重录的基线**：81/81 预设指纹全变（reason 已写入 fingerprint）；`test:dsp`

## 过程中发现并修掉的三个真 bug

1. **`PhaseInc()` 的单位错**：它返回的是「每输出样本」的相位增量，而块内循环在 2× 域里每输出
   样本推进两次。结果是普通路径**整体高一个八度**（220 Hz 锯齿实测 109 样本/周期 = 440 Hz，
   谐波检测显示基频为 0、只有 2f/4f）。修法 `inc = o.PhaseInc() / GS_SYNC_OS`。**不修的话本批
   所有离格底数字都不可信**——旧的错误签名恰好把 2f 当成了网格谐波，读出一个假的 −100 dB。
2. **BLEP 表跨自身跳变的插值**（P9.1c 已修，本批复用）：`sync_kernel` 在 `d ∈ [−1/64, 0)` 那
   一格必须补 `v += f`，否则该格拿到反号近满幅的修正，残余会爆到 −33 dB 再回落。
3. **`scripts/bench.mjs` 的计时门禁会静默失效**：原判据 `mean > TIMING_NOISE_MEAN_US (450 µs)`
   把「引擎自己的合法开销」当成了「宿主过载」，于是 P9.1b 之后 `verify:bench` 会永久只跑正确性
   断言并打印 `PASS (correctness only)`——门禁悄悄失效比红更难发现。已换成与 DSP 无关的
   `cpuProbe()`（300k 次无 wasm 浮点循环，取 7 次最小值），判据改为 **p50 < 60%** + 超标比例
   ≤ 2%，p99/mean/worst 只作信息打印；注释保留了 450 µs 为什么不再成立。

## 门禁怎么断言（`verify:audio`）

- **地板断言**：3 波形 × 8 音高，阈值按新实测**收紧**到 三角 −68 / 锯齿 −95 / 方波 −105
  （实测 −73.1 / −100.8 / −111.3，抖动 <0.3 dB）。
- **初相断言**：P9.1a 原来那条「同一个场景连做 8 次逐位相同」（当时读 0.00 dB）在新路径上
  **语义不再成立**——带限把基频对齐到 BLEP 网格，于是起始相位成了一个真实参数。改成
  「8 个全新场景的离散度 < 20 dB」（拦的是 P9.1c 那种 86 dB 爆发），实测锯齿 7.26 /
  方波 4.65 / 三角 0.61 dB。**刻意不再断言「8 个都 < −60」**，原因见下。
- 正弦 −105 断言不回退（实测 −119.4）。drive 叠混叠段 −33.4 → −59.5 dB 未变。

## 已知边界：滤波器共振 × 新振荡器（→ P9.6）

C7（2093 Hz）锯齿 + 工厂默认滤波（ladder，cutoff 18 kHz，**res 0.05**）下，约 **1/150** 个
全新 `note_on` 场景会读到 **−54.3 dB**（其余 −104…−114，下一场景立即恢复）。它**不是振荡器
的问题**：

- 单音长测连续 64 个 1 s 窗最差 **−101.6 dB**，0 窗超 −60，**没有** P9.1c 那种周期性爆发；
- 与 C 逐行同构、**没有滤波器段**的离线镜像在 1000 个初相下恒为 −70.5 dB；
- `res = 0` 时 150/150 干净；改截止（12/20/24 kHz）、换滤波类型（SVF 高通）、关掉全部 FX
  都不能消除；换音高（note 69/96）则干净。

对照：**改前旧核在同一探针下 150/150 全部超标**（默认 −44.4、no res −46.1、12 kHz −55.0、
SVF −13.9、note 69 −47.5、note 96 −40.2）。也就是说旧引擎在该条件下**从未**满足 −60 dB，
P9.1b 把它从「必然发生」压到「0.7% 抽签」。因为这是滤波器的账、且要动它就得改出厂音色
（再重录一遍全部指纹），它被立成独立批次 **P9.6**（见 `docs/NEXT-PLAN-2.md`），本批只把它
写进文档、并**刻意不让门禁变成每轮约 5% 的抽签**——那才是 P9.1c 教过的错。

未同步/未带限的路径逐位不变：切换 `OSC1_SYNC`、sub、FM/ring、过采样等既有断言全部保留。

## 发布时暴露的两条门禁问题（同一批修掉）

本批的发布先后失败了两次，**两次都不是引擎的问题，而是计时门禁在忙机上给出了假的判断**。
两条都改掉了，因为「门禁在机器变忙时误报」和「门禁悄悄不判」一样危险：

1. **`e2e/performance.spec.ts` 的启动预算只采一次样**。发布被 `interactive at 3720 ms`
   （预算 3200）挡住。按同一台机、同一条件跑**改前**（P9.1b 之前）的构建：**3785 ms**——
   只动过 wasm 的改动不可能让 JS 启动路径慢一秒。单独跑同一页只要 **526 ms**；在完整并行套件
   里取三次的**最小值**是 **2094 ms**，正好是预算当初标定的基线（2096 ms）。日志说明了一次采样
   为什么不够：三次分别是 `4092 / 2308 / 2094 ms`。宿主负载只会让一次运行**更慢**，所以最小值
   最接近应用自身的启动成本——与 `scripts/bench.mjs` 的机器探针同一条规则。现在取三次最小值，
   并加了 `GS1_BOOT_BUDGET_MS` 让有自己基线的机器（CI）覆盖预算。**预算数字 3200 ms 没动。**
2. **`scripts/bench.mjs` 的宿主负载判定有两个洞**。发布时 `most blocks fit the budget` 在
   loadavg 14.5 下判红（512/2250 块超预算）。其一，loadavg 只在场景开始前采一次，**跑的时候
   才来的负载看不见**（那条「跑完再采一次」的逻辑本来就存在，但被放在它所保护的断言**之后**）；
   其二，`busy` 的阈值是 `load > 0.75×核数`，把 72% 占用的宿主当成了空闲。阈值改为 **0.5×核数**，
   有实测依据：同一个 16 声部场景在 load ≈2 时 p50 **1169 µs（44%）**、在 load 5.8 时
   **1621 µs（61%）**——宿主单独造成 38% 的摆动，正是这个门禁要抓的回归量级。**性能阈值
   （量子 60%、超标比例 2%）一个字没动**，只是明确了「什么时候允许它下结论」。

改完之后，安静窗口里的发布给出了**真判定**：`[bench] PASS — timing judged (cpu probe 1097 µs
vs 1600 µs idle, load 1.6 on 8 cpus)`，p50 1101 µs（41%）、`[boot] interactive best 1267 ms of
[2525, 1419, 1267]`。这也是个教训：在共享开发机上，发布要挑宿主安静的窗口，代码里的探针只能
帮到这一步。

## P9.5 波表 / 采样音源高音区复核（v1.111.0）：**未达标 → 登记为已知边界**

计划 P9.5 的验收原文是「高音区（≥1 kHz）**波表**与**采样**音源的非谐波能量 ≤ **−60 dB**；
若已达标，写一条门禁把它钉住」。复核用的是**同一把 P9.1a BH-7 尺子**（4 s 整窗、精确 bin、
每个谐波 ±8 bin、清调制矩阵、真 wasm、整个参数块钉死），结论是**没有达标**：最差
**−25.8 dB**（vocal 表在 C8，4186 Hz）。这是**线性插值**的账，不改音色就修不掉，所以本批
把它登记为已知边界，并把实测值钉成门禁（**门禁不是 −60**，理由写在下面）。

### 测的是什么内容

- **出厂波表**：`dsp/wavetable.rs` 的 5 张 recipe 表（organ / hollow / vocal / metallic /
  glass），由 `OSC1_PW` 选择（`round(pw*4)`，与 UI 的 `wavetableValueToRecipe` 同一条规则），
  逐张 × 4 个音高实测。出厂内容就这 5 张，没有别的。
- **用户单周期波表**：2048 点锯齿（`gs_wavetable_import`，`WT_USER = 1`），与 `verify-audio`
  §5 用的是同一条。
- **采样**：**出厂没有任何采样内容**——采样是乐器级导入状态（`src/audio/userSample.ts`），
  预设只决定「放不放它」。所以复核用 `gs_sample_import` **确定性**导入一个：
  48 kHz、32768 点、**恰好 256 个 375 Hz 周期**（周期 128 点）、谐波 1..48、幅度 1/k：

  ```js
  for (let i = 0; i < 32768; i++) {
    let s = 0;
    for (let k = 1; k <= 48; k++) s += Math.sin((2 * Math.PI * k * i) / 128) / k;
    sample[i] = s;
  }
  ```

  `SMP_ROOT` = MIDI 66.2339（即 375 Hz）、`SMP_MODE = 1`（loop）、
  loop = `0.0078125..0.9921875`（最长级的 256..32512 点，含 **252 个整周期**）。loop 的两端
  落在同一相位，所以接缝在数学上无缝、不会被误读成混叠；每个谐波又都是 loop
  基频的整数倍，于是量到的离格能量只可能来自传输本身。所有数字在两次独立运行里
  **逐字节相同**（确定性）。

### 归因：表是带限的，**线性插值**不是

`dsp/wavetable.rs` 的 `every_level_is_band_limited_to_its_own_nyquist` 和 `dsp/sampler.rs` 的
stopband 测试都过，所以 level 本身没问题。残留来自**用线性插值读短表**：16 / 32 点的 level
被读成折线，折线自己的误差是一串高次谐波；超过 Nyquist 的那些折回 `SR − k·f0`，而那不是
这个音的谐波。四条独立证据：

1. **谱线位置就是折回来的谐波。** C7（f0 = 2093 Hz）实测最强的离格线在
   **4047 = 48000 − 21·2093**、**6140 = 48000 − 20·2093**、**8233 = 48000 − 19·2093**、
   **10326 = 48000 − 18·2093**、**1954 = 48000 − 22·2093** Hz。level 7 的表只有 7 次谐波，
   18–22 次是插值自己造出来的。
2. **独立 JS 复刻**（只有读表算法，没有引擎、没有滤波器）读出**同一批线**：
   22884 = 48000 − 12·2093、20791 = 48000 − 13·2093…；引擎里这些线更弱，只是 18 kHz 低通
   在衰减它们（总地板：复刻 −24.4 vs 引擎 −30.2 dB）。线的**频率**逐 bin 对上。
3. **表长扫描**（内容固定为同一组 7 个谐波）：16 点 **−24.4** / 32 −34.0 / 64 −46.4 /
   128 −58.5 / 256 −70.6 / 512 −82.6 / 2048 **−106.6** dB —— 每加一倍长降约 12 dB，正是
   线性插值误差的 **1/N²**。换插值器（16 点）：最近邻 −10.4 / 线性 −24.4 / 4 点三次 −30.4 ——
   换线性只买 6 dB，不是终点。
4. **第二把独立的尺子**：C7 的 4 s 恰好是 8372 个整周期，用**矩形窗 + 精确 bin + Goertzel**
   （无泄漏）直接量谐波线功率、再减出残差：vocal **−30.1**、organ −37.5、glass −32.7 dB，
   与 BH-7 差 ≤0.2 dB。不是窗口伪影。

采样还多一层，而且它在这个音区常常是**最强**的那条离格线：`Sample::render` 的读位置
`state.position` 以「level 采样数」为单位（这里到 4096），f32 精度约 5e-4 个采样；
波表的 `phase` 在 `[0,1)` 里，精度高约 10⁴ 倍。loop 本身无缝，于是这一点数值误差表现为
**一组以 loop 重复率为间隔的边带**：

- C7 整段 loop（8.18 Hz 重复）实测线在 2084.84 / 2101.50 Hz（= 2093 ∓ 8.2 Hz）；
  loop 减半后间距变成 **±16.4 Hz**（2076.60 / 2109.38），地板从 −35.3 改善到 −45…−48 dB。
- 把同一个读法在 JS 里用 f32 位置重放：−35.2 dB，最强的三条线
  **2084.84 / 2101.32 / 2101.50 Hz，与引擎逐 bin 相同**；换成 f64 位置：−44.7 dB，
  loop 边带消失，只剩插值像（16605 = 48000 − 15·2093）。

### 时域

同一条门禁里逐场景断言：峰值有界（实测 0.084–0.118）、无 NaN/Inf、最大相邻样本步进
0.075–0.094，而带限信号的物理上限是 `π × 峰值`（Bernstein：`|x'| ≤ 2π·f_top·P`，
`f_top ≤ SR/2`）＝ 0.265–0.370。另有一个**正控**：把干净缓冲里的一个采样打 +1.0，
同一个度量必须越界（实测步进 1.078 > 0.289）——门禁能红才有意义。

  还原后 PASS。**这一条同时就是「≤ −60 dB 未达标」的证明。**
- **自证 2（把阈值改成比实测严）**：采样顶棚 `−25` 临时改成 `−35` ——

### 结论与后续

- **结论：已知边界，未达标。** ≥1 kHz 的波表在 −25.8…−46.7 dB，采样在 −29.9…−31.0 dB，
  都不是 −60。听起来是「高音区有一点沙」，不是灾难，但和计划写的验收线差 30 dB 以上。
- **本批不动 DSP**（0–1 批）：修它要么让 `level_for` / `level_for(rate)` 选更长的 level
  （音色变暗），要么换更好的插值器（成本 + 音色都会变）——**两条路都会改变旧音色、都要重录
  全部 81 条预设指纹**，那是相容红线级，必须由父代理拍板，属于独立批次。门禁把当前行为钉住，
  任何「顺手改坏」都会红。
- 顺带记录：现有 §3c 与 §5 的「band-limited」断言、以及 Rust 的
  `an_imported_cycle_is_band_limited_at_a_high_pitch`，用的都是**半整数点**那把旧尺子
  （只抽 `f0*(k+0.5)` 几个频点），量不到这些折回来的线；P9.5 的 BH-7 复核对它们是更严的补充。
  它们都还绿着——这不是「表坏了」，而是**线性插值**的账，本批不动 DSP。

## P9.6 带限锯齿的窄窗查表缺陷（v1.112.0）：不是共振，是 BLEP 查表

P9.1b 交付后，计划把「C7 锯齿 + 工厂滤波下约 1/150 个全新场景读到 −44 dB」登记成
**滤波器共振 × 新振荡器**（见上文「已知边界」）。P9.6 的**配对实测否掉了这个归因**，
并把它修在振荡器里。

### 归因（同初相配对，真 wasm）

同一个初相就是同一次 `note_on` 序号：`gs_init` 不复位引擎的相位计数器，所以第 N 次
`note_on` 的起始相位永远相同。拿第 53 次（原坏点）做对照：

| 改动（其余全同） | 该场景读数 |
| :--- | ---: |
| 工厂滤波 `res 0.05` | −43.9 dB |
| `res 0` | −44.5 dB（**同一个坏点**；150 场景扫描同样 1/150） |
| OSC1 换正弦（滤波、res、cutoff 全同） | **−121.7 dB**，干净 |
| 近似纯延迟的 comb / 20 Hz 高通 | 坏点照样在 |

也就是说：**不是共振**（`res = 0` 一点没帮上；计划里「`res = 0` 时 150/150 干净」是换相位
序列后的运气），**也不是滤波器**（同一台滤波器换正弦就干净）。把该声部的**裸振荡器**
（未经滤波器，临时导出）取出来看，坏点上单样本阶跃 **1.906**（同一段里正常包裹是 1.071），
波形越界到 −1.45，前后完全正常——是 P9.1b 带限路径里**一次包裹的 BLEP 修正整级错了**。

根因与修法见 `docs/notes/hard-sync-aliasing.md` 的「P9.1c 的姊妹案例」：`sync_emit` 的
f32 表游走在 `t ~ 4096` 处把落在节点下方半个 ULP 内的抽头**舍入到正好 4096**，
于是读到跳变的右极限而不是左极限。

### 结果（真 wasm，C7 锯齿 + 工厂滤波，BH-7 尺子、4 s 窗、400 块稳定）

| | 150 个全新场景坏点数 | 最差 |
| :--- | ---: | ---: |
| 改前 | **1/150**（第 52 场，−43.9 dB） | −43.9 dB |
| 改后 | **0/150** | −110.4 dB |

P9.1b/P9.1c 刚挣到的带限余量不动：锯齿的键盘扫描、硬同步的 12 个场景、正弦的 −105 断言
全部以原值通过；`test:dsp 0.030735`、`verify:dsp:2x 0.030852`、81 条预设指纹**逐字节未变**
（缺陷只在 `xw < ~2e-6` 的窗口里改变输出，没有任何基线渲染命中它），所以**本批没有重录
任何基线**，工厂默认 `res` 也保持 0.05（它本来就与这个坏点无关）。

### 门禁与自证

`scripts/verify-audio.mjs` 新增 **P9.6 小节**：它把相位**钉成绝对种子 707**（一个实测坏相位，
改前 −44.8 dB），断言那一场 < −95 dB，另有 24 场全新场景的时域步进上界（< 0.13）作后盾。
相位用绝对种子而不是「第 52 场」是因为前面的场景数量会变，而绝对种子不会。

**自证**：把修复那一行改回去、重新构建，同一个门禁在同一台机上读

```

[audio] FAIL — the pinned P9.6 phase (note-on 707) stays on its harmonic grid
```

改回来后 `[audio] PASS`。

## P9.7 波表 / 采样高音区带限修到 −60 dB 以下（v1.113.0）：把 level 读成全长表

P9.5 把波表 −25.8…−46.7 dB、采样 −29.9…−31.0 dB 登记成已知边界，归因是**线性插值读短
mip level**（1/N²：16 点 −24.4、128 点 −58.5、2048 点 −106.6 dB）。用户授权改音色 + 重录
指纹后，P9.7 的修法不是「把每个 level 加长一点点」，而是**让每个 level 都是全长表**：
level 只决定**保留多少谐波**，不再决定**用多少采样点**。

### 为什么「加长 level」不能按原样做

P9.5 的表长扫描固定了谐波数（7 个）只加长表，所以读到 1/N²。但引擎里的 level 是**按表长
带限**的：一个 N 点 level 装到 N/2 次谐波为止。于是「把短 level 加长」会同时把它的谐波上限
抬上去，`h/N` 一直顶在 Nyquist 上，插值的弦误差并不下降。离线复刻（同内容、同读法、
BH-7 尺子、C8 4186 Hz）测得很清楚：

| 方案 | min level 长度 | 最差 dB | 备注 |
| :--- | ---: | ---: | :--- |
| 现状（逐级抽取变短） | 8 | **−24.2** | 复刻与引擎 P9.5 读数（−25.8）一致 |
| 只把最短 level 抬到 64 | 64 | −9.2 | **更差**：64 点表装 31 次谐波，弦误差更大 |
| 只把最短 level 抬到 128 | 128 | −8.4 | 同上 |
| 只把最短 level 抬到 256 | 256 | −8.2 | 同上（这就是计划里 1/N² 表的陷阱） |
| **全长 2048 × 9 级** | 2048 | **−113.6** | 谐波上限仍按八度降，级只当滤波器用 |

关键在第二步：C8 选中的 level 只有 **4 次谐波**，装在 **2048 点**表里，读一步只走
`4186/48000 = 0.087` 个表采样——插值几乎是逐样本，折回线自然没了。

### 逐音高 × 音源前后（BH-7 尺子、4 s 窗、400 块稳定、真 wasm）

因为 65 Hz 时全部工厂谐波都在引擎自己的 18 kHz 低通以内，**地板是滤波器的阻带**，不是表。

### 采样：f32 读位置边带 + 三次插值

采样单独一层的问题是 `ReadState.position` 是**以 level 采样数计的 f32**（最长 192000，
ULP ≈ 1.5e-2 个采样；读到 level 3 也有 3e-4）。loop 无缝，所以这点误差不平均掉，而是**以
loop 重复率为间隔**重放成一组边带。C7 的整段 loop 重复率 **8.31 Hz**：

| 读法 | 地板 | 最强离格线 |
| :--- | ---: | :--- |
| f32 位置（现状） | −27.3 dB | 22882.69 / 22882.51 / 22882.87 Hz（间隔 0.18 Hz = FFT bin） |
| f64 位置 | −30.1 dB | 22883.97 / 22883.79 / 22884.16 Hz（**与 f32 的那组不再是同一批频率**，f32 的量化误差被抹掉） |
| f64 + 4 点三次 | −28.9 dB（离线模型） | 引擎实测 −36.9 dB（本样本内容下） |

修法：`position`、`direction`（连带 `render` 的 `step`）全部改 **f64**，插值器从线性换成
4 点三次 Lagrange。表本身仍是 f32。引擎实测 **−29.9 → −33.4 dB**（note 84/96/108 三条
−40.3/−36.9/−33.4），并保留时域与正控断言。

**采样没有到 −60，如实报告，并给出具体代价。** 采样器的 level 就是录音本身，播放率 `r`
逼着 level 内容顶到表的 Nyquist，读步进 `r/2^level` 个采样的弦误差就是剩下的东西。按本批
离线模型拟合的标度（`20·log10(step·h/N) + 16.6 dB`，用实测 −25.1 dB @ step 0.698 / N 4096 /
h 48 定标）反推，达到 −60 dB 需要把读步进降到约 **0.055**，也就是每个 level 表长乘
**≈12–13 倍**：

| 场合 | 现状（最长 level × 总链） | 到 −60 需要的每级表长 | 该级 | 总链内存 |
| :--- | ---: | ---: | ---: | ---: |
| 门禁样本 32768 点，C6 (rate 2.79) | 8192 点 | **103 770** 点 | 405 KB | **≈2.5 MB** |
| 门禁样本 32768 点，C8 (rate 11.16) | 2048 点 | **23 585** 点 | 92 KB | **≈1.7 MB** |
| 1 s 样本（48000 点），C6 | 12000 点 | **139 700** 点 | 546 KB | **≈3.4 MB** |
| 上限 4 s 样本（192000 点），C6 | 48000 点 | **557 000** 点 | 2.1 MB | **≈18 MB（爆仓）** |

（链内存 = 各级表长之和 × 4 B；现状最长 level 是几何级，总链约为最长 level 的 2 倍，所以
「每级 ×12」等于「总链 ×12」。）结论：

- 对**短样本 / 高音**可行：门禁样本约 **+2.3 MB**（现状 0.25 MB → 2.5 MB），8 MiB arena
  还有富余，`gs_alloc_violations()==0` 的零分配约束不受影响（表是导入时一次性构建的）。
- 对**长样本不可行**：4 s 上限样本的 base level 本身就是 192000 点（0.73 MB），×12 后
  仅最长一级就 **2.1 MB**，总链 **≈18 MB ≫ 8 MiB**。要装下就得同时压低 `MAX_BASE_SAMPLES`
  （样本时长上限）或扩 arena——那是产品级的取舍。
- 因此**建议登记为已知边界**：本批把 f32 精度那一层修掉了、插值器升了一阶（−29.9 → −33.4 dB），
  并把「到 −60 需要什么」写成上面的表；不为凑 −60 去把采样内存变成不可控。

### 代价

| 项 | 改前 | 改后 |
| :--- | ---: | ---: |
| 波表 5 张 mip 总样本数 | 5 × 4088 = 20440（80 KB） | 5 × 18432 = 92160（**360 KB**） |
| 引擎 arena 余量（重启 4 次后） | 4655 KB | **4375 KB**（−280 KB） |
| 单表构建（2048 点 × 9 级，正弦和） | 4088 点 × 谐波数 | 18432 点 × 谐波数（≈5 倍算术，一次性、启动路径） |
| `gs_init`（best-of-9，同机） | **3.82 ms** | **12.06 ms**（+8.2 ms，一次性） |
| ABI / 参数 id | — | **不动**（`BASE_LEN`/`LEVELS` 都不是 ABI；导入容量本来就是 2048） |
| 采样器 level 内存 | — | 不变（`MIN_LEVEL_LEN`/抽取链没动） |

### 音色变化（客观）

- 变的是**折回成分**，不是谐波：五张表在 ≥1 kHz 的谐波网格与非谐波能量差从 ~26 dB 拉到
  ~100 dB 以上。听感上是高音区**更干净/更暗**（那点"沙"没了）。
- 响度基本不动：峰值与 RMS 在同一量级（C8 处 vocal 峰值 0.092 → 0.107、organ 0.096 →
  0.114，约 +1.3…+1.5 dB），因为每个 level 仍然逐一峰值归一化，换级不跳响度；差异来自
  18 kHz 低通以前削掉的那点能量现在本来就不存在。
- 81 条预设里**只有 4 条动**：`wtorgan` / `wtvocal` / `wtmetal` / `wtglass`（就是四条用波表
  的）。采样那层在本批的预设渲染里没有内容可读，所以采样预设指纹不动。

- 计划的 ≥1 kHz 波表验收线（≤ −60 dB）**达到**：最差 −98.0 dB（glass 在 1047 Hz），
