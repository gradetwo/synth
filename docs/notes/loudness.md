# 默认输出电平：为什么把 `VOICE_GAIN` 抬高 6 dB（2026-09-14）

用户报告：**「默认输出音量比其它软件低，系统音量要调很高才能听清」**。
本批把 `crates/synth-core/src/engine.rs` 的 `VOICE_GAIN` 从 **0.22 抬到 0.44
（+6.02 dB）**，并**记账式重录**受影响的基线。`LIMIT_CEILING`（0.95）与
`soft_limit` 的 knee（0.82）**未动**。

数值依据来自测量轨道 `p-loud`（分支 `p-loud`，只测不改；
`.tmp/wt-loudness/.tmp/loudness-report.md`）。本批执行它的推荐方案（路线 A）。

## 1. 根因：干净满幅正弦只有 −18.82 dBFS

真正的增益结构是 `gain = VOICE_GAIN × patch_gain`（`engine.rs` 立体声/单声道
两处）。把一条**干净满幅正弦**（osc1 sine、level 1.0、滤波 20 kHz、drive 0、
sustain 1、master 1.0、`PATCH_GAIN` 1.0）送进真 wasm：

| | peak | RMS | THD | limiter |
| :--- | ---: | ---: | ---: | ---: |
| 基线 `VOICE_GAIN` 0.22 | **0.115（−18.82 dBFS）** | −21.91 | 0.021 % | 1.000 |

−18.82 的分解：`VOICE_GAIN` **−13.15** + 等功率声像 0.707（**−3.01**）+
振荡器正弦幅度 0.9（**−0.92**）+ 梯形滤波器通带损失（**≈−1.7**）。
所以早期「整机低 13 dB」的说法**漏掉了后 5.6 dB**（那条读数是参数泄漏后的
脏正弦）。

另一个被澄清的点：真正在削波的是 `soft_limit()`（knee 0.82，绝对电平），
而且**基线就在工作**（16 音满幅和弦输出 peak 0.901 → 反推输入 ≈0.93 > 0.82）。
lookahead limiter 在绝大多数音乐性素材上**从不动作**——`gs_limit_reduction()`
返回的是**线性增益**（1.0 = 不动作），不是 dB。

首次启动的 patch 是 `DEFAULT_PARAMS`（`PATCH_GAIN = 1.0`），**不是** `pluck`
预设；`store.ts` 只把**名字**显示成 `FACTORY_PRESETS[0]`。所以只改预设 trim
治不到用户报的那个「默认」。`VOICE_GAIN` 是唯一一次性覆盖
「默认 patch + 91 预设 + 用户/随机 patch」的旋钮。

## 2. 为什么停在 +6：+9 实测证伪，+3 不划算

| | 基线 0.22 | +3 dB 0.31 | **+6 dB 0.44** | +9 dB 0.62 |
| :--- | ---: | ---: | ---: | ---: |
| 干净满幅正弦 peak dBFS | −18.82 | −15.82 | **−12.80** | −9.82 |
| 首次启动默认 patch peak dBFS | −20.02 | −17.02 | **−14.00** | −11.02 |
| 密集 bench（16 音）peak dBFS | −8.04 | −6.19 | **−4.89** | −4.01 |
| 密集 bench limiter | 1.000 | 1.000 | **1.000** | 1.000 |
| bank 中位乐句 RMS dBFS | −40.05 | −37.05 | **−34.03** | −31.07 |
| bank 最响预设 peak dBFS | −6.33（phonk） | −3.33 | **−0.73（phonk）** | −0.69 |
| 越过 0.82 膝的预设 | 0 | 0 | **1**（phonk 32 样点） | 3 |
| 2× 驱动抗混叠降幅（要求 ≥12 dB） | 26.1 | 18.4 | **13.7** | **11.2 ✗** |
| `preset-loudness` spread（门禁 <9.0） | 7.8 | **8.9** | **8.1** | 7.8 |

- **+9 dB 已证伪**：3 条预设触膝、`phonk` 被限幅器压 −2.79 dB，而且
  **2× 驱动抗混叠门禁真的掉到 11.2 dB < 12**——驱动信号变热后 1× 本身的混叠
  变多，是**真音质退化**，不是标定。
- **+6 dB 是甜点**：最响预设 `phonk` 的 peak 从 −6.33 抬到 **−0.73 dBFS**，
  正好贴满幅；只有 32/86400 个样点轻触软削波膝（限幅器 −0.06 dB，不可闻）。
  密集 bench 的 limiter 全程不动。
- **+3 dB 不划算**：只多 3 dB，却已经要动同样的门禁，而且
  `preset-loudness` spread 冲到 8.9（离 9.0 只差 0.1）。
- **+6 dB 的代价**：2× 抗混叠只剩 **13.7 dB（1.7 dB 余量）**；极端合成素材
  开始进入软削波/限幅（见 §5）。

## 5. 两条 `verify-audio` 步进门禁：相对化（标定，不是放宽）

`scripts/verify-audio.mjs` 里两条**绝对步进阈值**在 +6 后会判负，
但它们编码的是**某一个总线增益下的标定**，不是振荡器属性：

| 场景 | 0.22 | 0.44 | 比值 |
| :--- | ---: | ---: | ---: |
| P9.6 C7 锯齿 peak | 0.1159 | 0.2319 | **×2.001** |
| P9.6 C7 锯齿 worst step | 0.1061 | 0.2123 | **×2.001** |
| hard-sync 锯齿 peak | 0.1355 | 0.2710 | **×2.000** |
| hard-sync 锯齿 worst step | 0.1294 | 0.2588 | **×2.000** |

步进与 peak **严格同比例**（`gain = VOICE_GAIN × patch_gain` 整帧缩放），
所以步进/peak 的比值在两个增益下**逐位不变**：P9.6 是 **91.6% vs 91.6%**，
hard-sync 锯齿是 **0.955 vs 0.955**。写法改成：

- `P96_STEP_RATIO = 1.10`，断言 `step < 1.10 × peak`
  （旧绝对界 0.13 = 参考增益下 1.12 × 场景自身 peak；1.10 → 0.1275，
  **落在旧 0.13 之内**）。P9.6 的 bug 特征（其他相位步进 0.154 = 1.33 × peak）
  **仍被判负**。
- `HARD_SYNC_STEP_RATIO = 1.8`，断言 `jump < 1.8 × peak`
  （旧绝对界 0.25 = 参考增益下 1.84 × 锯齿场景 peak；参考增益下三个波形为
  0.2439 / 0.2107 / 0.2194，**每一个都在旧 0.25 之内**）。

**这不是"把门禁调绿"**：(a) 新界在参考增益下比旧绝对界**更严或相等**；
(b) 步进/peak 比值在两个增益下完全相同，说明没有任何新爆音，只是整体变大；
(c) 两向自证：把 `VOICE_GAIN` 改回 0.22 后，**新基线变红**（证明重录是真的），
而**相对化后的步进门禁仍绿**（证明它是尺度相关的，不是单边放宽）。
这也与文件里 wavetable/sampler 段早已使用的 `pi × peak`（Bernstein 界）
写法一致。

## 6. 极端合成素材上的取舍（重要，别误读成"偷偷放宽"）

`cargo test` 里有 **3 条单测、共 4 个界**在 +6 下判负。它们测的都是**刻意
做出来的极端素材**（12–16 音、OSC 全 1.0、master 0.75–1.0）；`soft_limit`
的 knee 0.82 与 `LIMIT_CEILING` 0.95 都是**绝对电平**，所以抬高 6 dB 必然让
极端素材更多地进入软削波/限幅。**这是 +6 dB 的固有代价，不是 bug**，而且
**音乐性素材不受影响**（bank 最响 −0.73 dBFS、spread 8.1、密集 bench
limiter 不动）。经父代理授权，按记账式更新这 4 个界：

| 测试 | 界 | 旧 | 新 | 实测（0.22 / +4.5 / +5.0 / **+6**） |
| :--- | :--- | ---: | ---: | :--- |
| `dense_chords_stay_clean` | 软削波样点占比 | < 0.1 % | **< 5 %** | 0.00 / 0.94 / 1.21 / **1.50 %** |
| `dense_chords_stay_clean` | limiter min_gain | > 0.98 | **> 0.5** | 1.000 / 0.790 / 0.748 / **0.668** |
| `limiter_catches_transients_without_clipping` | limiter min_gain | > 0.4 | **> 0.25** | 0.553 / 0.341 / 0.322 / **0.286（−10.9 dB）** |
| `stacked_voices_do_not_start_in_phase` | mix peak | < 1.2 | **< 1.2 × `VOICE_GAIN`/0.22** | 0.961732 / — / — / **1.923464（×2.0000）** |

- **第 4 条是纯标定**：`mix_l/r` 是**线性预限幅总线**，实测 0.961732 → 1.923464
  = **×2.0000**，正好等于增益比 ⇒ 与 `verify-audio` 两条步进门禁同类。
  写成 `1.2 × VOICE_GAIN/0.22` 后在 0.22 下仍等于 1.2，判词完全不变。
- **前 3 条是质量线，不是标定**：界描述的是「绝对限幅动作的多少」。
  守卫的用途都仍然成立——`dense` 当初防的是「曾经过载 ~25%」（1.50% 离 5%
  有 3.3 倍余量），`limiter_catches` 防的是「削爆而不是压住」（`peak <= 1.0`
  行才是削爆检查，`bus_peak` 已到 3.64，限幅器不工作就会硬削），`stacked`
  防的是「同相叠加」（比值判据不变）。**没有一条被改成"不许动作"**。
- **对照数据**（父代理要求）：即使只抬 **+4.5 dB**，`dense` 软削已达 **0.94%**
  （超旧 0.1% 界），`limiter` min_gain 已 **0.341**（超旧 0.4 界）⇒ 旧的
  绝对质量界对**任何** ≥ ~+4 dB 的抬升都不成立；少 1–1.5 dB 换回的余量，
  主要是 `dense` 软削从 1.50% 降到 0.94%（约 −0.06 dB 的响度差可忽略）。
  按父代理指示，本批仍按 **+6** 完成。

## 8. 疑虑

1. **2× 抗混叠只剩 1.7 dB 余量**（13.7 vs 12）。再抬增益会直接失去这条质量线
   （+9 实测 11.2）。**下一次想更响，应该改输出级设计（例如 limiter 的 make-up
   放在更前、或抬 `LIMIT_CEILING` 并把限幅器真正用起来），而不是继续加增益。**
2. **极端素材的余量变小是结构性的**：只要 knee/ceiling 是绝对电平，抬总线就
   必然花掉头部空间。§6 的对照数据说明这是连续的取舍，不是 +6 特有的悬崖。
3. 本批**没跑**（按纪律）：全量 `npm test`、`fuzz`、`bench` 计时、整链 `verify`、
   E2E、Firefox/WebKit。
