# GS-1 项目路线图 / Roadmap

> 基线版本：**v1.7.1**。本文档盘点现状、列出技术债，并给出分阶段（P0–P3）的开发与完善规划，每项都带验收标准与工作量估算，便于直接排期。

---

## 1. 现状盘点（v1.7.1）

**音频引擎（Rust → wasm32）**
- 减法合成：2 振荡器（6 波形、失谐、脉宽、声像）、Moog 梯形低通（24 dB/oct，Huovilainen 模型）+ SVF（HP/BP/NT，12 dB/oct）、双 ADSR、双 LFO、4 路调制矩阵、混响（Soundpipe `reverbsc`）、同步延迟、合唱/镶边/移相/过载。
- 工程特性：AudioWorklet 块处理（128–1024）、k-rate 参数、8 MiB 静态 arena 零分配、SIMD + 标量双版本运行时探测、Transferable ArrayBuffer 事件、负载过高按 4 步降复音。
- 16 复音、最旧/最弱偷声 + 8 槽待定队列无咔哒重触发、等功率声像。

**前端（React 18 + TS + Vite）**
- 三种工作区：模块网格、信号流画布、演奏模式（信号流承载）。
- MIDI 播放器：16 首内置曲目、SMF 导入、走带（循环/变速/移调）、现场录制、导出 MIDI/MP3（lamejs 懒加载）。
- 和弦识别（21 种模板 + 转位）、67 个工厂预设、A/B、撤销/重做、双语、PWA 离线 + 更新、响应式 + 触屏手势 + 触觉、内置双语指南（8 章）。

**质量门禁**
- 43 个 Rust 测试、~90 个 Vitest、23 个 Playwright E2E、WASM 双版本校验、DSP 基线、ESLint、GitHub Actions。

## 2. 已知问题与技术债

| # | 问题 | 影响 | 归属 |
| :-- | :--- | :--- | :--- |
| D1 | 参数为 k-rate 且直接写值，无平滑 | 快速拖旋钮可能有 zipper noise | 音频 |
| D2 | 主输出无限制器/软削波 | 多复音叠加可能硬削波 | 音频 |
| D3 | 撤销/重做只覆盖 patch 参数 | 布局/录制/导入不可撤销 | 状态 |
| D4 | 内置曲目含版权片段 | 分发合规风险 | 法务/内容 |
| D5 | `static mut ENGINE` 单例 + 固定 8 MiB arena | 无法多实例/多引擎对比 | 架构 |
| D6 | 信号流是固定拓扑的可视化 | 不能真正重排处理顺序 | 架构 |
| D7 | 无 MPE / CC learn，MIDI 输入较基础 | 外接控制器体验受限 | MIDI |
| D8 | E2E 仅 Chromium | Safari/Firefox 回归靠手测 | 测试 |
| D9 | WASM 用 fetch + instantiate，非 streaming | 首屏多一次往返 | 性能 |
| D10 | 画布动画在低端机可能吃帧 | 移动端续航/流畅度 | 性能 |
| D11 | 无视觉回归与性能预算门禁 | 视觉/性能回退不可见 | 工程 |

## 4. P0 — 音质与稳定性（v1.8.0，1–2 周）

目标：把"能弹、好听、不崩"变成"专业可用"，并补齐工程门禁。

### 4.1 参数平滑（解决 D1）
- 连续参数（cutoff、level、detune、mix 等）改为 **a-rate 线性/指数斜坡**：`AudioParam.linearRampToValueAtTime` 或在 worklet 内做 one-pole 平滑（推荐后者，保持 k-rate 接口但每块内插值）。
- 离散参数（波形、开关、同步）保持块速率跳变。
- **验收**：旋钮 0→100% 快速拖动无 zipper（频谱无周期性边带）；DSP 基线不回归；新增单元测试覆盖平滑系数。

### 4.2 主输出保护（解决 D2）
- 主总线加软削波（`tanh`）与可选简易限制器（前馈、快攻慢放）。
- **验收**：16 声部 + 满共振 + 满过载下输出不超 0 dBFS 硬削；THD 在可控范围；A/B 对比听感不糊。

### 4.3 完整撤销/重做（解决 D3）
- 历史栈扩展为"命令"模型：参数、布局（顺序/折叠/信号流位置）、录制片段、导入、预设保存/删除均可撤销。
- **验收**：E2E 覆盖每种操作的 undo/redo；`Ctrl/Cmd+Z` 在任意面板可用。

### 4.4 播放器增强
- A/B 段落循环（拖选区间）、节拍器、录制量化（1/16/1/8/三连）、录制倒计时、轨道静音/独奏。
- **验收**：单测（量化/循环边界）+ E2E（录制→量化→回放）。

### 4.5 多浏览器 E2E（解决 D8）
- Playwright 增加 **WebKit** 项目（Safari 引擎）与 **Firefox**；关键路径（启动、发声、导入、信号流）三浏览器跑通。
- **验收**：CI 三浏览器绿灯；Safari 特有回归（`performance`、`inset`、drop-shadow）纳入用例。

### 4.6 加载性能（解决 D9）
- `WebAssembly.instantiateStreaming` + 失败回退；首屏骨架与进度提示；`wasm-opt -Oz` 与 `--strip`。
- **验收**：4G 首屏可交互 < 2s；WASM gzip < 200 KB。

### 4.7 性能预算门禁（解决 D11）
- 脚本记录：WASM/JS/CSS 体积、首屏 TTI、单块 `gs_process` 耗时、16 声部 CPU 占用。
- **验收**：超阈值 CI 失败；每次发布生成性能报告。

## 5. P1 — 合成能力与演奏表达（v1.9–v1.10，1–2 个月）

### 5.1 Unison / 子声部
- 每个振荡器支持 1–7 个子声部，带失谐散布、相位散布、立体声扩散；supersaw 用 7×2 声部。
- **验收**：预设"Supersaw"听感达到商业参考；CPU 在预算内（可降子声部数）。

### 5.2 波表振荡器
- 单周期波表导入/内置库、线性插值、mipmap 抗混叠；波表位置可被 LFO/矩阵调制。
- **验收**：扫波表无混叠；导入 2048 点单周期文件。

### 5.3 滤波器扩展
- 新增 SEM（12 dB 多模）、Comb、Formant；每声部可串联/并联双滤波。
- **验收**：DSP 稳定性测试（高 Q 不自激失控）；预设展示。

### 5.4 调制扩展
- 新调制源：S&H、随机、包络循环、aftertouch、力度曲线；LFO 相位重置/单次/同步；矩阵扩到 8 槽 + 双极性。
- **验收**：矩阵路由可视化连线；单元测试覆盖双极性与深度换算。

### 5.5 效果扩展
- 效果并行/串联路由与顺序拖拽、卷积混响（IR 导入）、更多失真类型、主限制器。
- **验收**：IR 导入 < 2s；效果顺序切换无爆音。

### 5.6 MPE 与 MIDI Learn（解决 D7）
- MPE（每音弯音/压力/滑音）；CC 映射可编辑并持久化；MIDI learn 一键绑定。
- **验收**：外接 MPE 控制器 E2E；映射导入导出。

### 5.7 微调律
- Scala `.scl`/`.kbm` 导入、内置平均律/纯律/五度相生律。
- **验收**：音高偏差在 ±1 音分内；键盘映射正确。

## 6. P2 — 真正的模块化信号图（v2.0.0，2–4 个月）

目标：把"固定链路的可视化"升级为"可重构的信号图"。

### 6.1 动态信号图（解决 D6）
- Rust 侧：节点图描述（拓扑排序、每节点参数块、连接缓冲），支持任意顺序与并联；保持零分配与实时安全。
- 前端：连线拖拽、断开/重连、多选框选、对齐吸附、缩放平移、撤销/重做。
- **验收**：osc→fx→filter 与 filter→fx 顺序切换听感明显不同；16 声部性能不回归。

### 6.2 节点内联编辑
- 常用旋钮/开关直接渲染在节点上（可折叠为"紧凑/展开"两档），减少打开面板的频次。
- **验收**：节点内改动与详情面板双向同步。

### 6.3 布局与场景
- 信号流布局预设、分享（URL/文件）、场景切换（演奏模式 A/B 段落 + pad 触发）。
- **验收**：布局导入导出、场景切换无缝。

### 6.4 多实例引擎（解决 D5，可选）
- 若做 A/B 双引擎对比或分层，需要把 `ENGINE` 单例与 arena 改为可实例化。
- **验收**：两套引擎独立运行、互不干扰；内存预算可控。

## 7. P3 — 可访问性、国际化与分发（持续）

- **无障碍**：全键盘导航、ARIA live 播报（和弦/预设/状态）、屏幕阅读器流程、WCAG 2.2 AA 审计、Lighthouse a11y ≥ 95。
- **主题**：多套配色 + 跟随系统 + 高对比度审计；色盲友好校验。
- **国际化**：新增日/韩/西语；复数、日期、数字格式；RTL 预留。
- **文档**：rustdoc、架构图、贡献指南、CHANGELOG、短视频教程。
- **分发**：版本化 CDN + 回滚、分享短链/二维码、可选账号与云同步（离线优先）。
- **曲库合规（解决 D4）**：内置曲目替换为公版曲库 + 用户导入，或取得授权并标注。

## 9. 风险与决策

1. **版权（D4）**：现代影视/游戏曲目仅作短片段示范，建议 P0 内替换或明确声明；长期用公版曲库 + 用户导入。
2. **iOS 音频延迟**：AudioWorklet + 蓝牙设备延迟较高，提供缓冲/延迟提示与建议（有线/关闭蓝牙）。
3. **动态图重构成本（D6）**：先用 feature flag 渐进实现，保证固定链路路径不回退。
4. **移动端性能（D10）**：画布动画已支持离屏暂停与降帧；进一步按设备档位自适应（低端机 20 fps）。
5. **单例引擎（D5）**：除非需要多实例，否则保持单例以换取零分配与实时安全；P2 再评估。

## 10. 建议的下一步（本次之后立刻可做）

1. **P0.1 参数平滑** + **P0.2 主输出保护**：收益最大、风险最低，直接影响听感。
2. **P0.3 撤销/重做扩展**：把最近新增的布局/录制纳入历史，消除"改错了只能手动改回"的挫败。
3. **P0.5 WebKit E2E**：让 Safari 回归自动化，减少真机手测成本。
4. **D4 曲库合规**：明确内置曲目的授权/替换方案。

> 排期建议：P0 一个迭代内完成并发布 v1.8.0；P1 按 5.1 → 5.4 → 5.6 顺序推进（先做听感收益最大的 Unison 与调制扩展）；P2 立项前先做一版动态图技术预研（Rust 侧原型 + 性能评估）。
