# 真机回归清单 / On-device regression checklist（P0.1；P11.6 改成可勾选）

自动化测试覆盖不到真实触摸手感、iOS 的音频策略，以及主屏 PWA 的启动路径，所以每次发布前按这张清单
在 **iPhone、iPad、桌面** 各跑一遍。每条都是 `- [ ]`：**实测通过才勾**（勾 = 亲眼看到那条「预期」），
一条不通过就在 §7 记下来、不要勾。

**目标设备**（两条 iOS 腿都要覆盖；Safari 版本跟随系统）：

- iPhone：iOS **17.x 或 18.x**，Safari 17/18；
- iPad：iPadOS **17.x 或 18.x**，Safari 17/18；
- 桌面（对照，不替代）：Chrome 稳定版 + Safari 17/18。

**两个入口**：iOS 上 §1–§5 **每个入口各跑一遍**——A 是 Safari 里的标签页，B 是从主屏图标启动的
standalone PWA。两者共用一套渲染与音频代码，但启动路径、视口尺寸与音频会话不同，只测一个不算过。

## 0. 准备

- [ ] **入口 A（Safari 标签页）**：用 HTTPS 打开线上地址（`AudioWorklet` 与 Service Worker 都要求安全上下文）。
  - 预期：出现「启动音频引擎」遮罩、遮罩下方有诊断行（`SIMD … · WASM … · AudioContext …`）；地址栏是安全锁，
    控制台没有 error。
- [ ] **入口 B（主屏 PWA）**：在 Safari 里「分享 → 添加到主屏幕」，然后**从主屏图标**启动。
  - 预期：没有 Safari 的地址栏/工具栏（standalone），遮罩与诊断行照常出现；再次点图标直接进入应用，
    不会先跳回 Safari。
- [ ] **记录环境**：把设备型号 / 系统版本 / 浏览器版本填进 §7 的模板（入口 A、B 各一组）。
  - 预期：三项都能填全（这是判断「是不是只有这个机型/系统版本」的唯一依据）。
- [ ] **iPhone：确认侧边静音开关没有打开，系统音量 > 0**。
  - 预期：应用已设置 `playback` 音频会话，但静音开关与零音量仍会让后续发声项失败，先排除。
- [ ] **iPad：横竖屏各转一次，再进出一次分屏**。
  - 预期：模块网格重排，不崩溃、不丢当前补丁。

## 1. 启动与发声

- [ ] **1.1 打开页面** — 冷启动（杀掉标签页/App 再打开）。
  - 预期：启动遮罩出现，诊断行三项都有值（`SIMD ✓/✗`、`WASM simd/scalar`、`AudioContext suspended|running`）；
    没有卡在白屏、没有崩溃。
- [ ] **1.2 点遮罩启动** — 点遮罩中央的「启动音频引擎」。
  - 预期：**2 秒内**遮罩消失；诊断行变成 `AudioContext running`；若短暂显示「点按恢复」，在页面任意处再点一下
    应恢复发声（Firefox/Safari 的自动播放策略下允许出现这一步）。
- [ ] **1.3 点「DEMO 琶音」** — 启动后立刻点一次。
  - 预期：**1 秒内**听到起始音；示波器出现波形、频谱有能量、VU 表离开底部（三者至少两个肉眼可见）。
- [ ] **1.4 点屏幕琴键** — 依次点 3 个不同音高的白键。
  - 预期：每个键都发声（音高随之改变），按下的键高亮，松开后高亮消失、无余音。
- [ ] **1.5 按住琴键横向滑动** — 手指按住一个键，沿琴键横滑过 5 个键。
  - 预期：连续滑奏（像单音滑音），**无卡顿、无爆音、无断音**；键位高亮跟着手指走。
- [ ] **1.6 切到其它 App 再回来** — 切到别的 App 停留 5 秒以上，再切回。
  - 预期：顶部出现「音频已暂停」提示；在页面任意处点一下即恢复发声（提示消失，琴键重新出声）。

## 2. 键盘悬浮与隐藏

- [ ] **2.1 滚动模块区** — 在模块区上下滚几屏。
  - 预期：键盘**始终固定在视窗底部**，不随页面滚动；被键盘挡住的内容仍能滚出来（底部有留白）。
- [ ] **2.2 点顶栏「键盘」按钮** — 点一次。
  - 预期：键盘收起，右下角出现「⌨ 键盘」悬浮按钮。
- [ ] **2.3 点右下角悬浮按钮**。
  - 预期：键盘重新出现，悬浮按钮消失。
- [ ] **2.4 点键盘右上角的 ⌃**。
  - 预期：键盘收起（与 2.2 同样的结果）。
- [ ] **2.5 iPhone 上查看键盘** — 竖屏。
  - 预期：弯音轮/提示栏自动隐藏，键盘占满宽度，琴键不横向溢出。
- [ ] **2.6 点 OCT − / ＋** — 各点两次。
  - 预期：音域切换，琴键标签（C3/C4…）随之更新；切回原音域后标签与初始一致。

## 3. 旋钮与触控

- [ ] **3.1 按住旋钮上下拖动**（例如 CUTOFF）。
  - 预期：数值**平滑**变化，出现数值气泡并跟随手指；松手后气泡消失、数值保持。
- [ ] **3.2 同一个旋钮快速来回拖动**。
  - 预期：无跳变（不突然跳到 0/最大）、无卡顿、不触发页面滚动。
- [ ] **3.3 双击旋钮**。
  - 预期：复位到默认值（与刚打开时的数值一致）。
- [ ] **3.4 点 LED 开关**（例如滤波器过采样）。
  - 预期：状态切换且视觉同步；**热区比灯大**，点在灯旁边几毫米也能点中。
- [ ] **3.5 点滤波器类型 LP / HP / BP / NT**。
  - 预期：四种类型都能切换，响应曲线随之联动（不是只换文字）。

## 4. 模块折叠与拖拽

- [ ] **4.1 点模块标题栏的 ▾**。
  - 预期：该模块收起，只留标题行，其它模块上移；不丢参数。
- [ ] **4.2 点 ▸**。
  - 预期：模块展开回原样。
- [ ] **4.3 按住 ⠿ 拖动模块** — 拖到另一个模块的位置。
  - 预期：出现半透明标题浮层跟随手指，模块**实时换位**；松手后顺序固定。
- [ ] **4.4 把模块拖到屏幕顶部/底部边缘并停留**。
  - 预期：页面自动滚动，能把模块放到当前视口之外的顺序位置。
- [ ] **4.5 松手后刷新页面**。
  - 预期：模块顺序与折叠状态**保留**（与刷新前一致）。
- [ ] **4.6 预设库 → 重置面板布局**。
  - 预期：恢复默认顺序；键盘重新显示（若之前被收起）。

## 5. 预设与 PWA

- [ ] **5.1 切换上/下预设、随机、保存**。
  - 预期：参数与界面同步更新；保存后再切走再切回，能取回刚保存的预设。
- [ ] **5.2 打开预设库，用搜索/筛选** — 搜一个明显存在的名字，再切一个分类筛选。
  - 预期：结果与关键词/分类一致，没有空列表或错项。
- [ ] **5.3 断网后刷新**（飞行模式，或关掉 Wi-Fi）。
  - 预期：只要之前在线访问过，页面仍能打开、启动引擎并发声（Service Worker 命中缓存）。
- [ ] **5.4 发布新版本后刷新**（线上已有更新时）。
  - 预期：出现「新版本已就绪 · 立即更新」；点击后更新完成，且**不打断当前演奏**（引擎不重启、无爆音）。

## 6. 已知平台差异

这些是**预期行为**，不要当缺陷报：

- **iOS**：静音开关会静音 Web Audio；应用已用 `playback` 会话规避，但系统音量仍需开启。
- **iOS**：页面切后台会挂起 `AudioContext`，回来时点任意处即可恢复（§1.6）。
- **旧版 Safari（<16.4）**：自动加载标量 WASM 核心，功能一致、性能略低；诊断行会写 `WASM scalar`。
- **iPad 分屏**：横竖屏/分屏切换会重排网格（§0 最后一条）。
- **主屏 PWA**：没有浏览器工具栏，视口比 Safari 标签页高，模块可见数量更多——不是布局错误。
