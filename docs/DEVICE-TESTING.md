# 真机回归清单（P0.1）

自动化测试无法覆盖真实触摸手感与 iOS 音频策略，因此每次发布前请按此清单在
**iPhone、iPad、桌面** 各跑一遍。发现问题时请记录：设备型号 / 系统版本 / 浏览器
版本，以及启动遮罩下方的诊断行（`SIMD … · WASM … · AudioContext …`）和浏览器控制台报错。

## 0. 准备

- 用 HTTPS 访问（`AudioWorklet` 与 Service Worker 要求安全上下文）。
- 首次打开后，Safari 建议「添加到主屏幕」再测一次（standalone 模式）。
- iPhone 请先确认侧边**静音开关**未打开；应用已设置 `playback` 音频会话，
  但系统音量仍需 > 0。

## 1. 启动与发声

| # | 步骤 | 期望 |
| :-- | :--- | :--- |
| 1.1 | 打开页面 | 显示「启动音频引擎」遮罩与诊断行 |
| 1.2 | 点遮罩 | 遮罩消失，诊断行 `AudioContext running` |
| 1.3 | 点「DEMO 琶音」 | 听到琶音，示波器/频谱/VU 有反应 |

| 1.5 | 手指按住琴键横向滑动 | 连续滑奏，无卡顿/爆音 |
| 1.6 | 切到其它 App 再回来 | 顶部出现「音频已暂停」提示；点一下任意处恢复发声 |

## 6. 已知平台差异

- **iOS**：静音开关会静音 Web Audio；已用 `playback` 会话规避，但系统音量仍需开启。
- **iOS**：页面切后台会挂起 `AudioContext`，回来时点任意处即可恢复。
- **旧版 Safari（<16.4）**：自动加载标量 WASM 核心，功能一致、性能略低。
- **iPad 分屏**：横竖屏/分屏切换会重排网格，属于预期行为。
