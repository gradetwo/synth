## 二、下一阶段完整计划

排序原则：**用户每天用得到的工作流 → 音色能力 → 最贵的引擎重构 → 贯穿的工程与质量**。
括号里是「收益 / 成本 / 建议批数」。

### P5 工作流补完（高 / 中 / 4 批）

**P5.1 时间线编辑二期**（1 批）
- 要点：缩略时间线上**直接编辑音符**——点选、水平拖动移动、拖右缘改长度、双击删除；与钢琴卷帘双向同步（同一份数据、同一套撤销）；吸附 1/16；手机上以「选中 + 加减」按钮替代拖拽。
- 验收：单测（吸附、边界裁切、负向拖动）；E2E（拖音符 → 卷帘同步 → 撤销 → 重开仍在；手机视口可用）。
- 门禁：编辑进入 `store` 撤销历史；`npm run verify` 全绿。

**P5.2 曲目编排（片段）**（1 批）
- 要点：把一段音符折叠成 **clip**，可拖动/复制/循环铺排；片段内部仍用卷帘编辑；时间线显示片段块与循环标记；MIDI/WAV/MP3 导出跟随编排。
- 验收：单测（展开为音符列表的时间对齐 ±1 ms、循环次数、重叠规则）；E2E（复制片段 → 播放 → 导出时长正确）。
- 门禁：曲库 schema 升版 + 迁移样本（旧曲目无片段时行为不变）。

**P5.3 速度与拍号（tempo map）**（1 批）
- 要点：一首曲子多段速度与拍号；播放器、节拍器、预备拍、量化、导出全部跟随；分享码携带（压缩后仍很小）。
- 验收：单测（速度段边界 tick→秒换算、量化网格随拍号）；E2E（改速度 → 时间显示与播放一致 → 重开保持）。
- 门禁：导出的 MIDI 用自家 `parseMidi` 往返断言 tempo 事件正确。

**P5.4 录音 take 与叠加**（1 批）
- 要点：对当前层**叠加录音**、保留多个 take 并可切换/试听/合并；沿用录音量化。
- 验收：单测（叠加不丢原音符、切换 take 后导出跟随）；E2E（录两次 → 切 take → 播放内容不同 → 重开保持）。

### P6 声音能力（高 / 中高 / 5 批）

**P6.1 FM / PM 与环形调制**（1 批）
- 要点：OSC2 对 OSC1 的相位调制与环形调制，深度可由 ENV/LFO/矩阵调制；PM 的指数曲线与过深调制时的带限策略。
- 验收：时域（深度 → 边带数量）+ 频域（载波/边带能量）双域断言；DSP 指纹显式更新。

**P6.2 硬同步与子振荡器**（1 批）
- 要点：OSC2→OSC1 hard sync（同步点抗混叠）、每振荡器一个 sub（−1/−2 八度）、噪声混合量。
- 验收：频域（同步扫描的谐波结构与混叠 ≤ −60 dB）；时域（同步相位/周期对齐）。

**P6.3 滤波补全**（1 批）
- 要点：SEM 风格 12 dB 多模（LP/HP/BP/NT 连续可变）、双滤波串联/并联与混合量。
- 验收：频域（各模式斜率与中心频率、并联求和与解析解一致）；时域（阶跃响应无爆音）。

**P6.4 效果补强**（1 批，按收益取舍）
- 要点：bit-crusher（降位/降采样 + 抗混叠）、塑形 EQ（低/高架 + 中频扫）、可选瞬态整形；全部进入路由图节点池（沿用每节点状态）。
- 验收：每个效果时域（干湿混合、无爆音）+ 频域（目标曲线）；`verify:audio` 增加对应检查。

**P6.5 过采样开关**（1 批）
- 要点：失真/滤波路径可选 2× 过采样（默认关），基准记录开启后的成本；DSP 指纹分别记录两种模式。
- 验收：频域（2× 下混叠/镜像分量下降 ≥ 12 dB）；基准（开启后仍在预算内，阈值写清）。

### P7 节点图二期与内存模型（中 / 高 / 3 批）

**P7.1 延迟与卷积的多实例**（1–2 批，引擎级）
- 要点：**卷积**——IR 分区谱只读共享，每节点只分配 FDL 与输出缓冲；**延迟**——延迟线按「实例数 × 最长时长」的池在消息路径动态分配（音频线程零分配），UI 显示剩余可分配时长并封顶。
- 验收：单测（两个延迟节点时长/反馈互不影响、上限外拒绝并说明；两个卷积节点共享 IR 而尾部独立）；门禁：arena 断言 + `--long` 基准 + `verify-wasm` 越界检查。
- 风险：先做内存模型预研（Rust 原型 + 实测）再进 UI。

**P7.2 图内调制**（1 批）
- 要点：LFO/ENV 作为节点，边带深度连到任意节点参数（与现有矩阵并存），区分音频率与块率调制。
- 验收：单测（图内调制与矩阵叠加正确、无环）；E2E（拉调制线 → 看得到变化 → 重开保持）。

**P7.3 图模板**（1 批，可与 P7.2 合并）
- 要点：把「图 + 节点参数」保存为工作区模板（不进音色），一键套用；内置 3–5 个示例（双延迟、并行混响、失真分路）。

### P8 工程与质量（中 / 低中 / 6 批，穿插做）

**P8.1 本地 WebKit 标准化** — ✅ v1.79.0 完成
- 已完成：本地默认 `npm run test:e2e:webkit:wayland`（headless Weston）、`test:e2e:webkit:desktop`（桌面会话最快）、nightly 自动选 Weston → Xvfb → headless 并在记录里带 display 列；Docker 路径实测不可用并记录；已写进 ROADMAP 与更新记录。
- 关键更正（v1.79.0）：慢的根因**不是**显示栈或内核——空白页上 Chromium/Firefox/WebKit 都是 60 fps；是应用页每帧成本（全屏模糊 + 画布每帧重绘 + 启动页动画）。修完后 Chromium 空闲 7.5 → 60 fps，本机全量 E2E 8.7 → 4.2 分钟。详见 `docs/notes/ui-frame-cost.md`。
- 新增守卫：`e2e/performance.spec.ts` 断言音频运行中界面 > 20 fps（抓「退回每帧重绘」，不考核机器性能）。

**P8.2 视觉回归**（1 批）
- 要点：Playwright 截图基线（模块网格、路由图、卷帘、播放器、启动页 × 深/浅色 × 手机/桌面），阈值化比较，失败保留 diff。
- 验收：基线入库；故意改一处样式必须让它失败（自证有效）。

**P8.3 音频指纹扩到预设**（1 批）
- 要点：81 个工厂预设的频谱指纹基线（在现有 DSP 指纹与响度门禁之外再加一层），变化必须显式确认。
- 验收：新增 `verify:presets` 进 `verify`；故意改一个预设参数必须失败。

**P8.4 解析器模糊测试**（1 批）
- 要点：分享码、预设文件、`.gs1song`、SMF、Scala、WAV 解析器的随机/截断/超长输入测试（固定种子、可复现），断言「要么拒绝、要么产出合法对象」，不抛未捕获异常、不卡死。
- 验收：每个解析器 ≥ 1 万次随机输入（秒级），发现的问题修掉并留最小回归样本。

**P8.5 体积与启动预算**（1 批）
- 要点：初始 JS 150.8 → **140 KB gzip**（`songs.ts` 按需化或改曲包、指南/更新记录再拆）；新增「首屏可交互时间」预算（E2E 用 PerformanceObserver 测）。
- 验收：收紧后 `verify:budget` 仍绿；启动耗时不回退。

**P8.6 一键发布** — ✅ v1.79.0 完成
- 已做：`scripts/release.mjs` + `npm run release -- <version>`：发布前校验（版本/changelog 日期与中英双份/版本倒序/工作区干净）→ `verify` → Chromium E2E → `package` → `wrangler deploy` → 线上 `assets/index-*.js` hash 核对（含「边缘挂着旧清单就再部署一次」的重试）→ 附注 tag；任一失败即停，`--dry-run` 可演练。
- 同一套校验以 `npm run verify:release` 进本地 `verify` 与 CI verify 作业（CI 侧只要求日期真实且不在未来），文档见 `docs/notes/release.md`。
- 验收：dry-run 演练；失败路径（版本不符）实测退出码 1。

## 四、风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 时间线/片段改动动到播放器核心 | 先给数据模型加测试（对齐、循环、边界）再动 UI；片段进 schema 时带迁移样本 |
| FM/同步/过采样让 CPU 与混叠同时变差 | 每项都带时域+频域断言与基准门禁；过采样默认关，两种模式各记指纹 |
| 内存模型（P7.1）改坏 arena | 先原型与实测再实现；`--long` 基准的 arena 断言 + 越界检查 |
| 模糊测试挖出既有 bug | 每个发现留最小复现样本并修掉，进入解析器单测 |
| 本地 WebKit 慢导致夜间跑噪声 | 统一走 Weston；nightly 记录带 display 列；判据仍是空载整包 + CI |
| 视觉回归对字体渲染敏感 | 阈值化比较 + 只对关键视图做基线；差异产物保留 14 天 |
