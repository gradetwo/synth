## 二、优先级队列（按收益/成本排序）

### A. 采样导入：一次性采样作为振荡器音源（SMP）— ✅ 已完成（v1.50.0）
**收益**：鼓、人声切片、真实乐器单音都能直接当音源，是当前最缺的“声音来源”。
**要点**
1. `Wave::Sample` + `dsp/sampler.rs`：单声道采样按音高变速播放（`rate = note_hz / root_hz`），
   根音参数、播放模式（one-shot / loop / ping-pong）、起止点；**抗混叠**沿用波表的思路：按八度生成
   mipmap（对采样做带限抽取），高音区不产生混叠。
2. 每声部状态（位置、方向）随 `note_on` 复位、`note_off` 按模式处理；`MAX_VOICES` 内零分配。
3. 导入与持久化复用波表那一套：`wavefile.ts` 解码 → 截断到上限（建议 4 秒单声道，int16 存
   `localStorage`，约 512 KB）→ `gs_sample_import` 分析 → UI 一行（导入/使用/✕ + 波形预览）。
4. 参数：`SMP_ROOT`（根音）、`SMP_MODE`（三态）、`SMP_START/SMP_END`（可选，先只做内部默认）。
**验收**：① 单测：播放速率与音高准确（±1 cent）、mipmap 每级带限、loop 接缝无咔哒、拒绝太短/静音/非有限；
② 门禁：高音区无混叠（频域，≤ −60 dB）、导入电平与内置振荡器可比；
③ E2E：导入 WAV → 面板显示文件名 → 重载后仍在 → 导出音频包含它。

### B. 双实例（Layer / Split）— 建议 3 批
**收益**：叠加音色与键盘分区，是“多实例引擎”的最小可用形态，也是多轨的前置条件。
**要点**
1. 把 `Engine` 的“参数 + 声部池”提取为 `Instance`，`Engine` 持有 `[Instance; 2]`；主总线 / 效果链 / 限幅器
   共享（先做共享 FX，避免两套 FX 的 CPU 与 UI 复杂度）。
2. 参数空间：实例 1 保留现有 id（保证音色兼容），实例 2 使用**新增 id 段**（`INST2_*`），
   JS 侧用 `instanceId` 前缀映射；`instance enabled / key range / velocity range` 走 layout（工作区）而非音色。
3. UI：顶部（或 OSC 模块）加实例标签页 `1 / 2`，每个实例一套模块面板；键盘高亮分区。
4. 预设：预设只保存“当前实例”的参数 + 可选的 `both` 标记；场景保存两实例。
**验收**：① 单测：分区边界（按键落到正确实例）、叠加总响度不削顶、双实例静音/旁通；
② 门禁：CPU 与复音预算（双实例 16 声部仍 < 60% 预算）；
③ E2E：切实例 → 改参数 → 另一实例不受影响 → 重载保持。

### C. 多轨 + 时间线 — 建议 3–4 批
**收益**：把播放器从“单曲单轨”升级为可编排的多轨，配合导出即成为完整工作流。
**要点**
1. 数据模型：`Song` → `Project { tracks: Track[] }`，`Track { notes, instrument(instance), volume, pan, mute, solo }`；
   曲库格式加 `schema` 版本 + 迁移函数（见 F）。
2. 时间线 UI：轨道头（名称/静音/独奏/音量）+ 片段块（拖拽移动/复制/裁剪），与现有钢琴卷帘联动；
   移动端降级为列表式编辑（手机不做横向拖拽）。
3. 播放：每轨独立实例（B 完成后），按轨调度音符；录音落到当前轨；独奏/静音实时生效。
4. 导出：MIDI 多轨（SMF format 1）+ WAV 离线渲染（逐轨或整混）。
**验收**：① 单测：多轨调度时间对齐（±1 ms）、独奏/静音、迁移旧曲库；
② E2E：新增轨 → 粘贴音符 → 播放 → 导出 MIDI 轨道数正确；
③ 门禁：8 轨 × 16 声部的渲染负载仍在预算内（离线渲染无预算，实时播放需门禁）。

### D. 任意拓扑节点图（P2 完整版）— 建议 3 批
**收益**：把“信号链”升级为可自由连线的 DAG（并联/反馈禁止/多路混合），音色设计自由度最高。
**要点**
1. 引擎侧：`graph: [Node; N]`（源/效果/混合/输出）+ 邻接表；音频块按拓扑序渲染；
   先支持前馈 DAG（不允许环），每条边带增益；效果节点复用现有实现。
2. UI：Canvas 画布（节点卡片、拖拽连线、内联参数），与现有模块面板互为“简单/高级”视图；
   触屏用长按连线。
3. 与现有状态兼容：旧音色的“链顺序”自动映射为等价图，保证老音色不变。
**验收**：① 单测：拓扑排序稳定、并联求和、断线静音不炸；
② 门禁：图中每节点关闭时 bit 级旁通；③ E2E：连线/删线/重载保持。

### E. 工程项收尾（P0.5 / P0.6）— 建议 1 批 + CI
1. CI（GitHub Actions，`npx playwright install --with-deps`）：三浏览器跑 E2E；本机仍只跑 Chromium。
2. `instantiateStreaming`：优先流式编译，失败回退 `arrayBuffer`，Safari 走现有路径；记录 TTI 变化。
3. 顺带：`docs/DEPLOY.md` 增加 CI 徽章与缓存说明。
**验收**：CI 三浏览器全绿；首次启动时间不劣于当前（±10%）。

### F. 预设/工程 schema 版本化与迁移 — ✅ 已完成（v1.49.0）
1. 预设、分享链接、曲库、场景、`localStorage` 键统一带 `schema: N`；
2. 迁移表 `migrate_v(n) → v(n+1)`，加载旧数据时自动升级并提示（toast）；
3. 单测：每个历史版本样本都能迁移到当前版本且参数不被静默丢弃。
**验收**：旧分享链接/旧 `localStorage` 打开后音色一致（用固定的期望参数集断言）。

### G. 音频质量与性能增量 — 建议 1 批（按需）
1. 卷积混响：把每跳（1024 采样）的**分段乘加**摊到子块（当前集中在跳边界，实测平均负载安全，
   但极端设备上有尖峰风险）；`IR` 增加“电平/时长”门禁项。
2. 信号链：加一条“顺序 A vs B 频谱差异”门禁（确保重排确实改变声音，且在效果关闭时 bit 级旁通）。
3. 每季度一次夜间基准（长时渲染 + CPU 统计），结果写入 `docs/notes/`。

## 三、批次顺序建议

1. ~~**F**（schema 版本化，1 批）~~ ✅ v1.49.0 → 2. ~~**A**（采样导入，2 批）~~ ✅ v1.50.0 →
3. **E**（CI + streaming，1 批）→ 4. **B**（双实例，3 批）→ 5. **C**（多轨时间线，3–4 批）→
6. **D**（节点图，3 批）→ 7. **G**（按需）。

理由：F 是所有状态扩张的安全网（已就位）；A 成本最低、用户感知最强；E 把质量保障补齐；B 是 C 的前置；
D 收益最高但风险/成本也最高，放在状态稳定之后做。

## 四、风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 状态扩张导致旧数据/分享链接失效 | F 先行；所有新增字段给默认值；加载路径必须有迁移测试 |
| 双实例/多轨的 CPU 与复音预算 | 每批都跑性能门禁；实例数上限 + 负载监视降级沿用现有机制 |
| 卷积混响跳边界尖峰 | G1 摊平分段乘加；门禁记录尖峰比例 |
| 大块 UI 改动破坏移动端 | 每批跑手机/平板视口 E2E（现有 620/900 断点用例），触屏交互单独写用例 |
| 本机缺 webkit/firefox 系统库 | E 走 CI；本地不把 webkit/firefox 计入“全绿”判据 |
